# 个人助理可靠性调整：第一批实施与验证

日期：2026-09-06。基于当前本地工作树实施，未提交、未推送、未重新打包客户端。

本批完成设计评审中优先级最高的三项：会话连续性、后端定时触发、连接器状态可信度。并未宣称整个“优秀个人助理”目标已经完成。

## 已完成的调整

### 同一会话可恢复

- 新消息及助理回复保存真实 session 标识，保留原有用户/助理记忆命名空间和可见范围。
- 重建引擎、保存模型连接或重启服务后，按用户、助理和 session 精确恢复近期对话。
- 较早会话会翻页读取归档，不因其它会话新增了许多消息就被挤掉。
- 用户消息与对应回复关联排序，保留语音文本标识；恢复运行产生的回复也写回原会话。
- 近期助理自述不再把其它 session 的回复带进当前系统上下文。
- 尊重关闭记忆的选项：关闭写入时不持久化这轮用户与助理原文，关闭召回时不注入长期事实。

边界：仍是最近 24 条对话记录的短期窗口，不是无限上下文，也未实现长任务摘要。旧版没有 session 归属的归档保持原样，不推测归入某个网页会话；因此这类旧会话可能仍需用户补充上下文。长期用户事实仍按既有可见范围召回，并非全部跨任务共享被关闭。

### 定时触发移到服务端

- 服务启动时检查一次，之后每 15 秒检查固定能力任务与既有港股提醒。
- `/api/capabilities/due` 和 `/api/hk-reminders/due` 只返回状态，不再靠读取接口触发执行。
- 继续使用已有持久任务队列、worker、审批和交付回执，没有绕过授权。
- 每日任务成功入队后持久保存本次计划标识；重复检查、重启、取消该次任务或清理历史队列不会导致同一次计划自动重跑。
- 顺序为先保存队列、后确认计划；中间中断时通过幂等标识找回同一任务。
- 修复队列落盘失败后的内存回滚，避免未真正保存的记录被后续检查误认作成功入队。
- 调度源报错时保留失败来源名称，并继续检查其它来源；状态接口返回运行标志和最后检查时间。

边界：仅在本机服务运行时执行。关机、完全退出客户端或系统休眠期间不会执行。启动或唤醒后的检查可发现当日到期的每日任务，不补跑已过去的每一天。没有新增一次性提醒、云端常驻执行或手机通知。已入队/执行失败事项仍按原有运行记录与人工重试机制处理。

### 连接器状态与实际运行条件一致

- 统一判断启用状态、provider 是否挂接、运行错误及执行授权。
- 同类扩展有多个时，优先使用满足就绪条件的扩展，不让断开的第一个扩展遮住可用扩展。
- 已安装但未连接显示“待连接”，缺少授权、停用和运行错误都有区别说明。
- 仅配置联网搜索不再把“浏览器”连接器标成已连接。
- 连接测试只统计选中连接器的读取工具，避免其它扩展的工具使测试误报成功。
- 界面区分运行时就绪与账号数据已验证；已安装扩展的管理按钮滚动到插件区域，不再误打开文件导入。

边界：运行时就绪、读取工具发现成功，都不证明真实账号权限、外部网络或某项写操作已经通过验证；界面明确保留这个区别。

## 验证结果

最终运行：

- `npm run typecheck`：通过。
- `npm test`：396 项，395 通过、0 失败、1 跳过。较评审基线增加 14 项测试。
- 跳过项仍为需要真实 Blender 的三维核验，与本批调整无关。
- 本批修改文件的 `git diff --check`：通过。

新增验证覆盖：

1. SQLite 数据库关闭重开后恢复网页会话；不同会话、不同用户不串线。
2. 较早会话跨页恢复、旧版未标记会话隔离、恢复运行回复归属、记忆关闭行为。
3. 没有页面请求时计时器到期入队、重复启动、停止计时器、重启去重。
4. 入队失败、中间持久化中断、真实磁盘路径写入失败后的安全恢复。
5. 时间推进模拟下的时区、次日、唤醒后检查、停用边界和调度源错误隔离。
6. 未挂接、启动失败、未授权、已停用连接器不可报告就绪；同类连接器选择正确。
7. 完整 HTTP 服务：在没有任何页面或 HTTP 请求的情况下，后台任务自动执行并保存结果；随后多次读取状态及重启服务，仍只保留同一个计划运行。
8. 完整 HTTP 服务连接本机模拟模型：保存模型配置及重启服务之后，同一会话的历史确实进入模型请求，另一会话的标记没有进入。

测试全部使用临时目录、本机模拟模型或离线回复，没有使用用户个人数据库或真实模型 key。成功交付的模拟/离线结果用于验证执行链路，不代表真实大模型内容质量已经验收。
