# 任务到执行技能：附件转交

本次接续 task-skill-handoff-2026-09-07.md，补齐其中“附件需重新选择”的限制。未引入统一任务调度器。

## 已实现

- 从任务中的“准备执行技能”进入时，文字和最多 8 个原始附件一起转交。原任务保留文件，不自动提交。
- 原始 File 通过同源 BroadcastChannel 在浏览器内存中转交；不把文件正文、Base64 或文件对象写入 localStorage、sessionStorage 或 URL。文字转交沿用一次性 sessionStorage 令牌，版本 2 只额外记录附件数量，兼容旧版本文字载荷。
- 30 秒接收超时、数量不一致、无效文件、弹窗阻止、取消均报错并清理临时通道。目标页已有内容时不覆盖。
- 执行技能准备页新选择的附件也改为延迟读取，支持多文件追加。点击“开始执行”后才读取正文；期间禁用准备区域，重复点击不重复提交。
- 解析失败、空正文、不支持的编码、截断结果以及附件正文超过 24000 字符会阻止提交；原件保留，成功解析部分可以缓存重试。
- 浏览器草稿只保存待处理附件的名称、大小及标记。刷新或关闭页面后原件需要重新选择，不能凭缺失附件的草稿静默继续执行。
- 保留原有执行器、输出格式及记忆选项；从任务转交的新准备页默认关闭偏好记忆。

## 验证结果

- 158 项相关测试通过，0 失败；TypeScript 类型检查通过。
- 新增单元测试：原件转交不提前读取、草稿不保存文件、缺失原件拒绝执行、数量不一致、取消与超时清理、解析失败保留原件、成功结果缓存。
- 独立 Edge 实测：从任务上传合成 TXT，进入演示制作准备页后收到真实 File、pending 为 true；原任务仍保留同名附件，子窗口 opener 已断开。
- 准备页拦截真实任务提交接口，返回隔离测试失败：点击前读取计数 0，第一次点击后 1，第二次重试仍为 1；两次请求均被拦截，提交载荷含附件材料，失败后原件仍存在、界面解锁。
- 截图：outputs/skills-migration-20260907/attachment-preparation.png。
- 没有真实任务入队、付费模型调用或服务重启。办公文件解析异常通过既有隔离接口测试验证，本轮浏览器路径使用 TXT，未声称完成全部办公格式实机验收。

## 仍需继续

- 在同一任务 ID 下执行多个技能，统一执行进度与成果引用。
- 专业技能仍需点建议入口并确认执行，主任务按钮没有变成完整的自动技能调度器。
- 附件不是持久文件引用：刷新需重新选择。原件长期复用及统一文件库关联另行设计。
- 转交不假装继承来源页的模型/工具配置，执行前应在目标准备页确认。
