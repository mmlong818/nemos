# 出站代理（2026-09-09）

小丑鱼此前没有任何代理支持。在需要代理才能访问模型服务商的网络里，应用发出的请求
直接超时，表现为「无法连接模型服务」，而后台计划任务会安静地一次次失败。本次补上
代理，并把它的作用范围写清楚。

## 默认关闭，没有代理的人行为不变

设置保存在 `outbound-proxy.json`，与 `network-policy.json` 平级，默认 `mode: "off"`。
解析不出代理时程序完全不改动全局 dispatcher，因此没有代理的用户看不到任何差别。
`off` 模式即使环境里存在 `HTTPS_PROXY` 也一律不生效：替用户改出站路径必须是显式选择。

三种模式：

| 模式 | 行为 |
| --- | --- |
| `off` | 默认。不安装 dispatcher，不读环境变量。 |
| `environment` | 读 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`。两个代理变量都没有就等于关闭。 |
| `explicit` | 使用设置里保存的地址。 |

接口是 `GET` 与 `POST /api/outbound-proxy`，形状与 `/api/network-policy` 一致。与网络策略
一样，这两项都只有文件和接口，没有设置界面。坏文件不阻断启动，读取失败的事实记在
`loadError` 里由接口返回。

## 覆盖范围，以及不覆盖什么

覆盖的是**进程内基于 `fetch` 的出站调用**，模型调用属于这一类，包括聊天、流式、
模型目录读取、资格检查和 Responses 通道。

不覆盖的有三处，必须说清，否则会被当成比实际更强的保证：

- **网页读取不走代理。** `local-http-security.ts` 用 `node:https`，并且把连接钉在 DNS
  解析出的地址上，那是它的 SSRF 防线。它不用 `fetch`，所以既不会被代理，也不会因为
  这里装了代理而被削弱。需要代理才能读的网页，本版读不到。
- **被 spawn 的 MCP 子进程不受约束。** 与网络策略同一个边界：Node 的 `--allow-net`
  是全有全无，AppContainer 也不按主机过滤。
- **出站允许与拒绝名单不管模型调用。** 那份名单从一开始就只作用于网页读取。代理和
  名单是两件事，这也是代理设置单独一个文件、没有并进 `network-policy.json` 的原因：
  塞进去会让人以为名单也覆盖了模型调用。

## 回环与私网无条件直连

自定义服务商的预设地址是 `http://127.0.0.1:1234/v1`，给 LM Studio 与 Ollama 用。如果
按代理设置一刀切，配了代理又用本机模型的人会把请求发给代理然后失败。因此
`localhost`、`127.0.0.1`、`::1` 一律直连，并且会读取当前保存的模型地址与各服务商预设，
把其中属于回环或私网的 IP 字面量一并并入直连名单。公网模型地址不会因为它是模型地址
就绕过代理。

判定不做 DNS 解析：解析一次等于把访问意图泄露给 DNS，与网页读取那条路「策略先于
解析」的顺序保持一致。undici 的 no-proxy 匹配只认主机名与后缀，不认网段，所以私网
地址必须逐个并入，指望用户自己写 `NO_PROXY` 是不可靠的。

## 凭据

显式地址**不接受内嵌用户名与密码**。带密码的代理地址是密钥级数据，落盘就该像模型
密钥那样受 DPAPI 保护，而 DPAPI 只有 Windows，那等于给别的平台造一个存不了的设置。
需要登录的代理请用 `environment` 模式：凭据留在用户自己的环境变量里，本程序不持久化
它，也不在接口、状态或日志里回显。对外状态只给出协议与主机。

## 为什么不用 NODE_USE_ENV_PROXY

那个环境变量只有 Node 24 以上才认。本包 `engines` 允许 22.19，便携包里的 `node.exe`
又是打包机 PATH 上的版本（`Build-Clownfish.ps1` 直接复制），所以它会在一部分用户那里
静默无效。改用 undici 的 `EnvHttpProxyAgent` 配 `setGlobalDispatcher`，三个值全部显式
传入，Node 22 以上都工作，且模式行为由本程序决定而不是一半由 undici 决定。

替代方案是把八处 `fetch` 改写成 `node:https` 加手写 CONNECT 隧道以免新增依赖，但那会
动到流式工具调用的解析，而那部分有一批「半截 JSON 绝不执行工具」的测试，风险明显
更高。`undici` 就是 Node 内部已在使用的库，MIT。

## 验收

单元测试覆盖默认关闭、环境模式缺变量即视为关闭、回环与私网无条件直连、显式地址
拒绝凭据与多余成分、对外状态不回显凭据、以及解析不出代理时不碰全局 dispatcher。

整合测试起一个真实的本机代理夹具，绝对形式请求与 CONNECT 隧道都记账：装上代理后
指向不可解析主机的 `fetch` 确实经过代理并取回响应，而回环目标一次都没有经过它。
清空直连名单后该断言会变红，已实测确认它是承重的。

本轮没有验证需要登录的企业代理、`https://` 形式的代理端点，以及代理下的网页读取，
因为网页读取按设计不走代理。
