# 模型目录与资格检查采用说明（2026-09-09）

## 范围

本次实现让小丑鱼保存、展示和收藏服务商返回的任意**合法模型 ID**。这不表示程序宣称任意第三方模型、任意 API 协议或任意能力均受支持：适配层只有明确的 `openai-compatible` 与 `anthropic` 协议；未知 provider 会被明确拒绝，而不是回退到另一家服务商。自定义服务必须由用户选择协议并填写规范化 API 地址。

模型名称不是能力判断。目录保留所有合法 ID（包括名称看似嵌入、图像或音频的型号）；能否进行文字对话、流式输出或工具调用，只由该连接上的显式资格检查结果决定。

## 持久化与资格

保存连接的活动型号、模型目录、收藏和资格检查各自有不同语义：

- `favoriteModels` 是跨连接保留的用户偏好。收藏既不发起网络请求，也不代表该模型已通过检查。
- `modelChecks` 记录 synthetic 文字、流式和工具往返检查的结果，不能作为收藏或默认选择的替代物。
- 每个持久连接有一个不从 API Key 推导的本机 opaque `connectionRevision`。目录有独立的 `catalogConnectionRevision`；检查也带其实际检查时的 revision。
- provider、协议、规范化 base URL 或凭据改变时，旧检查不会复用；旧目录可显示为 stale，但不会成为资格依据。
- 检查结果在七天后过期。过期、未知或 revision 不匹配都应显示为待验证，不能被自动刷新、自动执行或自动换成另一型号。

保存、切换连接、设置页加载和选择模式变更均不发起模型推理请求，也不会从目录的前几个候选中静默替换用户的 model ID。目录刷新是明确操作，但只读取服务商目录；“检查模型”是另一项明确操作，且仅检查用户指定的一个 ID。

## 调用成本与安全边界

一次显式模型检查使用不含用户历史和真实工具的 synthetic 请求，可能包括文字、流式、工具调用与工具结果续轮，通常最多四次实际 provider 模型请求。因此检查页面必须将其视为可能计费的操作；失败、过期或切换后绝不在后台补做检查。

API Key 不会写入模型 ID、revision、目录、检查详情或公开状态；持久化仍只保存经 Windows DPAPI 保护的凭据。公开状态中的 revision 是无密钥关联的 opaque 本地标识，供 UI 判断目录与检查是否属于当前连接。

## 兼容策略

旧 v2/v3 单连接文件没有 revision。读取时只在这一次迁移中把其既有检查绑定到该保存连接，以避免无故中断已经验证的当前默认模型。v4 文件必须保留自己写入的 revision；错配、伪造或缺失绑定的检查会被丢弃，不能在重启或保存时“洗白”。

环境变量驱动的旧运行时保持有限兼容；持久连接公开 `requiresVerification`，提醒旧的未验证默认连接需要用户显式确认。新建或切换后的持久连接在当前 revision 上未通过文字检查时不会执行；使用工具还要求该 revision 的工具检查通过。恢复 checkpoint 同样经过当前连接的资格保护，旧任务 metadata 不能绕过新连接权限。

## 验收

专项覆盖保存零推理请求、显式单 ID 多能力检查、收藏、目录 stale、v4 重启 round-trip、伪造 revision、过期检查、端点切换和 Astra Responses 协议。最终综合验收执行 `npm run check`：839 项测试中 838 项通过、0 项失败、1 项跳过（需要本机 Blender 的三维环境检查）；build、typecheck、许可证与发布元数据检查均通过。
