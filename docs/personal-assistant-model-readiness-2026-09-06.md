# 个人 AI 助理：模型连接与任务选模第二批调整

日期：2026-09-06。承接 [第一批可靠性调整](personal-assistant-reliability-2026-09-06.md)。本批聚焦“选中的模型确实可用，并且任务真正使用它”，没有增加开发引擎，也没有推送远端或重新打包客户端。

## 已实现

### 1. 目录候选与验证结果分开

读取模型目录后，不再直接把第一项当成可用模型。设置页记录每个已检查型号的文字回复、流式输出、工具往返结果以及检查时间。目录中的其他型号明确显示为未检查。

验证复用应用实际调用适配器，全部使用合成测试内容，不发送用户聊天记录、不连接业务工具、不执行真实操作：

- 一次非流式文字回复。
- OpenAI 兼容接口的一次流式文字回复。
- 一个固定参数的模拟工具调用，以及把随机回执作为工具结果发回后的最终回复。必须收到正确函数名、有效参数和正确回执，不能只凭模型说“成功”判定通过。

每个型号最多 4 次请求，单次输出上限 512 tokens；单型号检查总超时为 20 秒。检查可能产生服务商费用，页面已提示。Anthropic 适配器目前使用完整 JSON 回复，记录为 buffered，不宣称原生流式已经验证。

### 2. 自动检查较新候选，保留手动选择

- 自动：按目录提供的创建时间降序，缺少时间时保留服务商顺序；最多检查前 3 个候选，优先采用通过工具往返检查的型号。
- 如果这 3 个候选只有文字回复通过，则保留其中排序最前的文字型号，明确显示工具限制；需要工具的请求会明确报错，不会冒充已经执行。
- 手动：只检查填写的型号。提交新 Key、刷新目录或者切换对话模式不会把手动型号换成另一项。
- 认证失败、额度/频率限制、服务故障或网络超时会停止继续尝试，不会不断轮换型号消耗请求。
- 不再把日常聊天自动路由到未经验证的预设“轻量型号”。日常默认与已选默认模型一致。

“较新”只是目录排序参考，不是质量排名或全球最新发布保证。OpenAI 的 `created` 字段表示模型创建时间，而非账号能力检测结果或官方发布日期：[Models API](https://developers.openai.com/api/reference/typescript/resources/models/methods/retrieve)。工具验证按照“模型发出调用—应用返回结果—模型读取结果”的往返方式设计：[Function calling](https://developers.openai.com/api/docs/guides/function-calling)。

### 3. 任务选模贯穿真正执行

已有对话和新建任务首条消息前均提供模型选择器。切换时先检查，检查不通过时保留原选择；“跟随默认”与固定某个型号分别保存。目录中已消失的旧选择不会被静默替换。

修复了两层遗漏：任务页面进入文稿/能力执行分支时没有传递模型，以及引擎进入工作模式时忽略显式模型。现在任务执行、流式执行及后续补全/修复使用本次运行的模型与工具权限，不修改全局默认或未来定时任务配置。

### 4. 配置与密钥保护

- 检查失败时，不写入新配置；先完成加密及临时文件写入，再原子替换配置文件，随后切换活动配置。
- 同一服务商换了地址也不会把旧 Key 自动发送过去。变更服务/地址/协议/Key 后不沿用旧连接的检查结果。
- 并发检查/保存互斥，避免慢请求覆盖较新配置。
- 配置仍使用当前 Windows 用户的 DPAPI 加密；成功保存后清空页面密钥输入框。公开状态不包含 Key。
- 模型服务的原始 HTTP 错误正文不展示或保存，避免网关把密钥回显进错误信息。
- 不提供 `/models` 的兼容服务（404/405/501）可使用手动型号；自动模式会提示改为手动，不虚构完整目录。
- 接受粘贴完整 `/chat/completions` 或 `/messages` 地址，并归一到 API 根地址；修复 IPv6 本机地址识别。

- `npm test`：413 项，412 通过，0 失败，1 跳过（需要真实 Blender 环境的既有测试）。本批新增 16 项模型单元测试和 1 项完整服务集成测试，并扩展已有工作模式/UI 回归断言。
- JavaScript 语法检查：设置页脚本和任务页内嵌脚本均通过。
- 完整服务集成：自动跳过不可用型号、手动固定、验证失败保持配置文件不变、切换任务模型不改变默认、文稿实际使用所选模型及工具权限、重启恢复、无目录服务、新旧 Key 隔离、加密保存、并发更新互斥。

重跑说明：中间一轮全量测试出现多个测试进程失败；其中 4 个文件单独重跑的 23 项全部通过。原因尚未确定。关闭隔离浏览器后再次执行未修改命令的 `npm test`，最终得到上述 412 通过、1 跳过、0 失败（约 23 秒）的结果；不能据此把之前的进程失败归因于某个已证实的环境原因。

浏览器回归使用 agent-browser 驱动独立 Edge 会话，实际填写设置、保存、切换、发送消息并检查页面错误。验证了自动筛选、密钥输入清空、手动失败保留原配置、任务切换失败保留原型号、新建任务首条消息前选模，以及切换对话模式后仍保留选择。未记录到浏览器脚本错误。

## 尚未声称完成的部分

- 检查结果是时间点快照，不是持续健康监控；不能保证账号后续不欠费、不限流或模型永不下线。
- 自动只检查有限候选，不对目录中所有模型发起付费扫描；目录若分页，当前范围是此次服务返回的目录页。
- 未对真实服务商 Key 进行在线验收，未验证视觉、语音、嵌入、多模态或真实业务工具的端到端能力；文字/工具探针不等于复杂任务质量评测。
- 旧配置不会在启动时偷偷发送验证请求，尚未检查时明确标记；用户再次保存或选择具体型号时进行检查。
- 仍是一个当前活动服务连接下的多型号选择，不是多个服务商账号同时活动的故障切换系统。
- 尚未重新打包或更新运行中的正式客户端。源码改动需在新进程/后续客户端包中生效。

后续仍按个人助理主线推进：把长期目标、待办承诺和交付结果联系起来，并在这套可验证模型连接上做真实任务验收。
