# 模型等待状态关联任务

本轮增加 ModelAdmissionState（waiting / active / released）回调，统一模型适配器在获得名额前后发出状态；队列释放位于 finally，观察器异常不泄漏名额。

ChatAgentContext 将通知传到文字协作及隔离规划器，使用现有任务 checkpoint 保存 modelAdmission（阶段 ID、状态），不保存连接凭据或资源 HMAC。任务详情只读取运行中任务的最新检查点：等待显示“等待模型”，获得名额后显示“模型执行中”。取消、失败、成功以及后续其他检查点不沿用旧状态。

验证：28 项相关单元测试、类型检查通过。覆盖等待/获得名额/释放顺序、观察器异常、取消、不同资源、详情终态与后续检查点防误标；未进行浏览器端真实排队验收，未调用付费模型。

范围：当前是文字协作任务详情；其他任务类型、列表卡片、精确队列位置、持久等待顺序、跨进程调度和 429 退避仍未接入。恢复通用 Agent 运行时只有调用方重新提供通知回调才会记录状态，函数不写入持久元数据。

当前 8787 服务未重启，新后端通知需要下一次启动加载。仅刷新前端不能让旧进程发出新状态。用户数据未迁移或清空。

## 后续：列表与详情统一

列表摘要接口新增 modelAdmission，仅在运行中且最新检查点值为 waiting / active 时返回。前端 modelState / modelLabel 由列表和详情共用，已有检查点数组优先于摘要，空检查点不回退到旧摘要。底层 job.status 不改变，因此原分组、筛选与取消机制保持不变。

验证：29 项相关测试通过（含 2 项 HTTP/真实队列隔离集成），类型检查通过；新增序列化后列表/详情一致、终态清理以及摘要接口终态断言。仅验证渲染函数及隔离接口，没有进行浏览器端多任务并发全流程验收。旧后端不返回新字段时前端兼容原状态。

其他流程任务尚未发出模型等待检查点，不会据此显示虚构等待。当前线上服务仍未重启。
