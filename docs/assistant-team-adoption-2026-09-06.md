# 主助理与专职 Bot：第一批改造

日期：2026-09-06。用户批准参考 Grok Bot 的实际工作模式，目标仍是“个人长期使用的优秀 AI 助理”，不是克隆 Grok，也不恢复已移除的开发引擎。

## 决策

保留一个主助理小丑鱼。简单任务独立完成，需要不同职责时调用专职角色；角色共享工作成果，不默认共享全部个人历史。交接、恢复和收尾由持久任务系统负责，不能只让模型互相 @。

依据是本机 Grok Bot 实测：角色记忆与内部交接成立；首轮内容仍有漏项；群聊核验后停顿，人工提醒才完成；无关记忆标记曾经由交接传播。借鉴有效流程，同时避免把上述行为照搬成产品保证。

## 本批已实现

| 原设计基础 | 本批改造 |
| --- | --- |
| 主助理与专家角色 | 新增专职 Bot 工作规则管理；内置资料整理、独立核验；支持自定义、编辑与停用 |
| 持久任务与运行时 | 同一 AgentJobQueue / AgentJobWorker 执行有界协作，不另开一套后台执行服务 |
| 模型连接与选模 | 当前连接下选择已检查模型，任务冻结型号与规则版本；换服务或 key 后不悄悄用另一连接恢复 |
| 受控交接 | 记录接收、返回、失败、时间、规则版本、输入指纹及正文 |
| 恢复与取消 | 复用相同输入下的成功回执；中断后继续未完成步骤；取消不产生最终成功结果 |
| 完成门槛 | 有效最终结果＋全部必填字段＋来源格式齐备才交付；界面明确“待审阅”，不称事实已验证 |
| 主助理入口 | 对“助理团队 / 专职 Bot / Bot 协作”请求按需暴露审批工具，结果链接到团队工作区 |

入口：任务页、工作页侧栏“团队”，或 `/bots`。流程：新建协作任务 → 填目标、共享材料和字段 → 按需选执行/核验 Bot → 开始 → 查看回执及最终结果。不选角色就是主助理单独处理。

## 运行与数据边界

- 最多两名执行者、一名核验者、一次主助理汇总；每阶段最多 120 秒。不是自由无限群聊。
- 执行者只拿原始任务，彼此不串上下文；核验者与主助理拿必要的已返回任务成果。
- 调用现有模型运行时，强制 `toolMode=off`、空记忆 scope，不经过会自动召回个人档案的普通聊天引擎。
- Bot 工作规则是用户手动保存的配置，不是系统推断的个人事实。任务资料不会进入长期记忆。
- 主助理发起工具不接受模型生成的 objective/materials，直接绑定当前用户请求；字段标签必须出现在本条请求中，不能夹带私人记忆。工具仍需既有审批。
- 材料会送给用户配置的模型服务。此边界不是承诺模型输出不会犯错，也不能阻止用户主动在共享材料/规则中填入私人内容。
- `assistant-bots.db` 保存按用户区分的工作规则；现有 `agent-jobs.json` 保存任务快照、回执与最终结果。已有 personas、记忆库、模型密钥和客户端目录不迁移、不覆盖。
- 页面刷新或关闭不驱动执行；后台运行时继续。进程重启复用已持久回执；正在调用但尚未留下回执的模型步骤可能重算并再次收费，不能宣称外部 exactly-once。

## 设计与界面

按 frontend-design 流程审视现有工作台后沿用其主题：画布 `#f4f1eb`、白色成果面板、墨色 `#211f1c`、强调色 `#ad315f`、分隔线 `#d9d9de`。界面用现有 Segoe UI 字体栈、时间/指纹用等宽字；不新增外部字体依赖。

布局为“最近任务 / 交接记录与最终结果”，窄屏改成上下结构。特色不是头像墙或能力数量，而是一条能展开正文、看见输入指纹的回执时间线。审视后去掉了不必要的统计卡与装饰动画，保留目标、状态、共享范围和结果。

## 验证

新增单元与 HTTP 集成测试覆盖：规则持久化与用户隔离、版本冲突、停用、重复请求幂等、冻结规则、主助理单独执行、实际三阶段调用、无工具/无记忆 scope、缺字段失败、只重试汇总、取消、阶段超时、重启保留、工具注册及审批属性、禁止模型参数夹带私人材料。

本地模拟模型＋真实服务/队列的界面验收：创建自定义 Bot、选择整理与核验角色、提交含来源和必填字段的任务、无需额外消息自动显示最终交付、打开回执、刷新恢复、390px 窄屏展示。截图在工作区 `outputs/assistant-team-20260906`。这些是执行链路验收，不是对真实模型事实正确率的宣称。

最终验证：`npm run typecheck` 通过；前端脚本 `node --check` 通过；`npm test` 共 482 项，481 通过、0 失败、1 项既有 Blender 实机测试跳过。额外覆盖了运行中断后真实服务重启接续，已返回整理回执未重复调用。未运行本轮付费模型质量测试，未重新打包便携客户端。

## 尚未纳入这一批

1. 专职 Bot 独立聊天及可审阅的角色私人记忆增删改；不会把工作规则管理宣传成完整记忆管理。
2. 把现有文件、来源连接器、技能按权限绑定到新 Bot：当前团队明确仅文字处理，现有能力入口继续可用。
3. 从本次任务中选取资料/产物交接、与长期事项关联、后台结果回到原始对话的通知流程。当前通过 `/bots?job=…` 取回。
4. 市场导入、导出分享、第三方插件安装与定时团队任务。
5. 数字/来源真实性的确定性校验器、真实付费模型质量回归、跨天稳定性和便携客户端重新打包。

这些是后续增量，不应通过放宽默认记忆共享或恢复开发引擎来“补齐”。本批未推送远端，未覆盖现有安装包。
