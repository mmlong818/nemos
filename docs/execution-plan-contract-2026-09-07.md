# 自主协作第一步：执行计划契约

状态：后端基础已实现并接入旧文字协作运行器；自动规划与专业技能编排尚未上线。

## 本次实现

- 新增 execution-plan.ts：主任务 ID、计划版本、步骤执行者、目标、交付要求和依赖。
- 服务端白名单校验，不接收提案中的工具授权字段；拒绝未知字段、无效执行者、重复步骤/依赖、缺失依赖、循环、自依赖、孤立步骤和超过 8 个步骤的计划。
- 最终交付必须依赖所有工作步骤，避免产生无人消费的执行结果。
- 计划哈希绑定任务、修订与完整步骤内容；旧计划回执不得用于新计划。
- 纯调度选择函数限制最多两个并发名额，已有运行步骤占用名额。仅依赖成功的未开始步骤可就绪；失败、阻塞、取消不自动重试。
- 原 assistant-team 运行器将固定流程转为显式依赖契约，阶段仅接收其依赖阶段的成果。保留原顺序、回执输入哈希、权限及请求数据格式。

## 未实现的边界

就绪选择函数不是原子领取器，没有独立启动工作；目前旧任务仍顺序执行。模型规划器、计划持久化与修订 API、专业技能适配、统一材料/成果引用、并发执行及计划 UI 仍待接入。不得将这一步展示为用户已可自主组队。

执行者白名单由服务器调用方提供；当前适配的是已冻结的旧任务角色，不借此改变旧任务入队快照语义。后续新计划须按当前用户的已启用角色及权限重新建立白名单。

## 验证

- 2 项真实 HTTP/队列隔离集成测试通过，覆盖提交、收尾、回执恢复、取消、服务重启，以及进程中断后复用已保存成果。
- npm run typecheck 通过。
- 使用隔离模拟模型，不调用真实付费模型、不写用户任务数据；没有重启 8787 线上服务。
