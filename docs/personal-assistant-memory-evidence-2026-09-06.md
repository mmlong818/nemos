# 个人助理：记忆证据接入与剩余事项

日期：2026-09-06。适用范围：当前本地工作树，版本仍为 0.2.3，未发布。

## 本批完成

### 1. 召回正文不再被一律宣称为事实

应用过去把 `nemos-memory` 的召回结果压成正文列表，丢掉来源、置信度和纠正关系，
随后在提示词中称其为“关于对方的真相”“可放心引用”。

现在聊天、流式聊天、任务交付与主动记忆工具统一携带有界的结构化证据：

- 记忆编号、层级、类型、主体与主体解析状态。
- 来源类型、抽取器、转述次数、原始说话人、会话与消息标识。
- 原有置信度、候选/晋升状态、证据覆盖与冲突标记。
- 创建/生效时间、来源事件和纠正关系标识。
- 正文被截断或采用检索节选时明确标记。

不生成“用户已确认”字段；`confidence=high` 不等于用户确认，
`authoritative=true` 也不证明资料真实或属于用户。缺失元数据标为未知，
不会伪造来源、置信度或原文引述。

保留 `userFacts` 作为兼容的界面摘要，实际模型提示使用 `memoryEvidence`。
本批没有修改记忆核心依赖、数据库结构或用户已有记忆。

### 2. 限制旧事实和原文旁路

- 应用的当前事实上下文额外过滤非活跃状态、已失效/过期记录，以及明确标为
  引用、假设、玩笑、角色扮演的记录。SDK 的历史查询推断不能绕过该过滤。
- 归档原文不直接升级为用户事实；本批新增的来源投影只使用已召回记录中的标识，
  不按标识扩读其它任务原文。
- `memory_recall` 工具改用同一套证据投影，关闭归档证据兜底；它查询当前派生事实，
  不再充当历史失效事实或跨任务原始聊天记录搜索器。
- 当前任务自己的历史恢复仍由已有的会话归档机制负责，没有移除。
- `off` 和 `preferences` 模式不会开放通用记忆工具；恢复运行时明确的空权限范围
  仍保持为空，损坏的范围元数据也不会恢复额外权限。

JSON 转义、固定数据边界和提示规则用于区分历史资料与操作指令；这不是“彻底解决
提示注入”的证明。真正的工具权限仍由运行时控制。`memoryMode=off` 控制长期记忆召回，
不等于清空当前任务对话，也不等于关闭写入；写入仍由 `memoryWriteMode` 单独控制。

### 3. 中文交付偏好的有界兜底

测试复现：没有配置嵌入检索时，已保存“用户偏好简洁标题和三列表格”，
用包含“按……交付”的完整任务指令搜索可能返回空结果。SQLite 当前 FTS 的中文
短语匹配对措辞敏感；这不等于记忆没有保存。

仅在初次没有选出偏好时，从当前用户、可见 scope 的长期偏好/做法层取得有限候选，
排除敏感、冷却、失效、非字面及明确第三方资料；再通过 SDK 召回做正式准入。
不以本地候选直接绕过核心的显著性、晋升、争议和可见性规则。

上限：前 8 个可见 scope，每层 50 条；最多 12 条候选正文、每条 1600 字符，
最终最多使用 4 条。预览与实际任务共用选择逻辑。
这修复了已复现的偏好漏召回，不代表任意中文事实、任意规模资料库都能完整召回。

## 仍未完成：按个人助理主线排序

1. **统一的个人长期事项。** 把目标、当前阶段、下一步、截止时间、等待条件、相关资料、
   授权范围与结果回执组织到一起。现有任务/运行和“待你处理”是基础，但不是完整的
   个人目标与承诺管理。下一批优先做“进行中的事”最小闭环。
2. **任务成果到长期记忆的确认流程。** 当前任务正文和附件刻意按归档处理以防污染；
   需要将明确确认的决定、稳定偏好、约束有选择地沉淀，并支持查看与撤回。现有记忆页
   已有来源查看、结构化记忆纠正和忘记入口，不应重复宣称这些完全不存在。
   新的候选/不确定性说明尚未成为完整的用户侧确认工作流。
3. **真实个人任务验收。** 使用用户选定的真实模型和实际资料，验证连续多日使用、
   复杂文件交付质量、失败恢复与授权边界；在线邮箱/日历等需先确定目标服务和账号，
   不自动配置外部账号或发起真实写操作。
4. **客户端发布与分发。** 这几批源码尚未重新打包、提交推送或替换当前客户端。
   仍需干净 Windows 环境安装/启动、实机休眠唤醒、后台通知、数据迁移与分享使用验收。

次要已知限制：Buzz 待处理入口每类最多读取 500 条记录；偏好兜底有上述窗口；
当前仍是一个活动服务连接下选择多个型号，不是多服务商故障切换；关机后的执行需要
另行确定常驻执行环境。没有必要为了“合并更多”而引入整个 Buzz 服务栈或恢复开发引擎。
