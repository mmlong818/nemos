# 能力提升计划

更新：2026-08-13

## 成功标准

目标不是复制 WorkBuddy，而是让普通用户通过一句话获得可检查、可修改、可继续执行的成果。

- 核心任务首次成功率可测量；
- 产物可以继续编辑，不是一次性文本；
- 长任务可以暂停、恢复、取消和追溯；
- 外部操作有明确授权，失败不会破坏原文件；
- 新机器的必要配置步骤可见且尽量自动完成；
- 公开能力描述与实际验证一致。

## 第一阶段：补齐执行闭环（最高优先级）

### 1. 文件与 Office 工作台

**不自研 Office 编辑器，也不把“原位编辑”作为小丑鱼内核任务。** Office 格式、排版、公式、图表、批注和协同编辑的复杂度远超当前项目合理边界。

采用“成熟内核适配器 + 可靠降级”方案：

1. 首选评估 ONLYOFFICE Docs：编辑 DOCX、XLSX、PPTX 的能力完整，Web 嵌入接口成熟；正式集成前必须解决 Developer 商业授权或 AGPL 开源义务、Document Server 部署和安装体积。
2. 备选评估 Collabora Online：基于 LibreOffice，通过 WOPI 接入；CODE 只适合测试、小团队或个人使用，正式产品需要评估受支持版本和独立服务部署。
3. 桌面 Office/WPS 适配器只作为增强：用户机器已经安装且存在稳定、合法 API 时启用；不依赖逆向接口，不把特定厂商组件打包进核心。
4. 无编辑内核时继续使用当前安全降级：保留原文件，提取为可编辑内容，明确转换损失，导出新文件。
5. 自研范围只包括文件管理、版本、授权、AI 修改指令、适配器协议和编辑器宿主，不包括排版引擎。

先做两周技术验证，不直接进入产品开发：用同一组 20 份脱敏复杂文件比较 ONLYOFFICE 与 Collabora 的格式保真、API 可控性、Windows 本机部署、冷启动、内存、安装体积、授权和二次分发条件。验证通过后只选择一个主内核。

验收：编辑器内修改真实 Office 文件后仍可由 Microsoft Office/WPS 正常打开；表格、图片、批注、页眉页脚、公式、图表、母版和讲者备注按测试清单核对；卸载或服务失效时不会破坏原文件，并自动回退。

### 2. 开发项目工作台

在现有 Pi Agent、工作区授权、修改提案和回滚之上补齐：

- 项目文件树和搜索；
- 命令、测试和构建过程的实时记录；
- 文件差异审阅与逐文件接受；
- 并行任务使用隔离工作树；
- 失败原因、重试入口和可恢复检查点；
- Node、Git、Python 的环境检查与引导，不默认暴露 CLI。

验收：选择 10 个不同技术栈的真实小项目，完成定位问题、修改、测试、审阅、回滚全过程；不得越过授权目录。

### 3. 统一交付物

所有能力使用统一产物协议：来源、版本、生成步骤、验证状态、可编辑格式、导出格式、后续动作。聊天、能力页、文件页和任务页看到的是同一份成果，而不是复制件。

## 第二阶段：让能力真正可复用

### 4. 技能生命周期

补齐发现、安装、权限预览、启用、升级、停用、卸载、版本回滚和健康检查。安装前显示其需要的文件、网络、命令和账号权限。

### 5. 连接器闭环

首批只做高频通用连接：本地文件、浏览器、GitHub、邮箱、日历、企业文档。每个连接器必须有只读模式、测试连接、最小权限和失效提示。

### 6. 领域能力包

优先建设五个可验证能力包：

1. 深度研究：来源计划、网页取证、冲突核验、引用和更新检查。
2. 办公文档：文稿、表格、演示的模板与质量检查。
3. 项目开发：代码、测试、文档、发布准备。
4. 运营分析：数据清洗、指标口径、图表、周报。
5. 财务分析：只做资料整理与分析支持，强制来源和时点，不伪造实时数据。

## 第三阶段：形成产品优势

### 7. 记忆驱动的工作习惯

只让记忆影响少量高价值行为：称呼、文风、排版、常用格式、审阅严格度和常用工作区。每次任务明确展示本次采用了哪些偏好，并允许单次忽略。

### 8. 后台与并行工作

任务可以并行、定时和从已有上下文继续；完成后进入统一审阅队列。避免把多任务重新包装成群聊。

### 9. 质量评估体系

为每项能力维护固定样例、自动检查、人工检查和回归记录。能力状态只允许：实验、可用、已验证、生产就绪。

## 暂不追赶

- 为展示丰富而增加大量角色；
- 厂商专属云部署入口；
- 没有稳定数据源的实时票务、酒店和餐饮库存；
- 不能说明权限边界的桌面全自动控制；
- 只生成漂亮界面但无法继续编辑的伪产物。
