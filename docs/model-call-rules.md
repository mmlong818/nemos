# 模型调用规则

运行规则的版本化正本是 [`model-call-policy.ts`](../sdk/typescript/examples/companion/model-call-policy.ts)（`schema: nemos.model-call-policy`，`version: 1`）。修改调用边界时，同步更新规则、适配器和合成测试；不要把调用参数的预算或思考强度散落硬编码在各功能中。

## 开发约束

- 新增模型调用要接入统一规则，并明确任务类型、单次及任务预算、能力校验、空正文与重试处理。若现有旁路尚未接入，须在交接中标明覆盖状态，不得宣称全局统一。
- 用户显式选择的思考强度优先；只向明确支持该参数的型号发送。未知型号不附加未经确认的思考强度。
- 没有正文也没有工具调用的模型结果不得记为成功。自动重试最多一次，且只限未输出、无工具副作用、仍有预算的调用；每次已发起的尝试都占用预留额度。流式输出和工具调用不自动重试。
- 预算按输出 Token 预留，不能据此承诺输入 Token 或人民币费用的硬上限；价格未知时尤其不能承诺金额。

## 首版覆盖与限制

`llm.ts` 的共用文字模型入口已用于普通对话、流式对话和 Agent 续跑，并在此执行输出预留及空正文检查。规则只在同一服务进程内计数；服务重启后不恢复历史任务预留。已发起调用的身份留在进程内，累计达到 10,000 个不同身份时会拒绝新任务。需另行设计可持久化且有界的任务生命周期，不能通过按时间清理预算让同一任务重新取得额度。

第二阶段 A 已将 `server.ts` 的智谱工具翻译、润色、ASR 校正接入共用文字网关。工具连接继续使用独立加密 Key → `TOOL_ZHIPU_API_KEY` → `ZHIPU_API_KEY` 的优先级，沿用工具所选型号（默认 `glm-5-flash`）；每个 HTTP 工具请求有独立预算身份，单次最多预留 2600 输出 Token，连同一次安全重试最多预留 5200。无工具、非流式且空正文时最多重试一次；ASR 校正两次空正文后保留原转写。网关不会把服务商自由文本错误透出。

上述三处工具调用的每次已发起尝试同样写入现有文字调用账本，按 `tool_text` 用途记录状态与服务商报告的用量；账本只保存元数据，不保存工具 Key、提示词或正文。账本统计不等于持久预算。

第二阶段 B 的持久额度接线见下文；完整任务生命周期及媒体、生图、视频旁路尚未覆盖，当前不能视为全局费用控制。

## 持久预算接线（第三阶段安全子集）

服务端在数据目录创建独立 `model-call-policy.db`。新 Agent 文字运行以稳定 run ID、新协作作业以队列幂等键作为 owner；预算库在首次服务商调用前，单个 SQLite 事务中绑定 owner、已保存的预算 UUID 与发行的 `taskInstanceId/budgetKey`。同一 owner 换 UUID、旧任务行已回收、容量耗尽时拒绝调用，不重新发行额度。协作所有席位共用 owner，自动重试每次另行预留。调度准入后、发送前将尝试标为 started；此后失败或进程中断均保留扣额，只有尚未开始的预留可退。旧 Agent 续跑及旧协作作业缺少版本标记时拒绝发起模型调用。

owner 墓碑不自动删除；数据库达到 100,000 个 owner 或任务、1,000,000 次尝试时拒绝新增预留。明确完成的 Agent owner 与成功完成的协作作业在持久终态写入后关闭预算；关闭前所有尝试须为 `finished` 或 `cancelled_before_start`。未结算的 `reserved`、崩溃留下的 `started` 和结果不明的 `ambiguous` 均阻止关闭与回收。协作子阶段共享同一 owner，不会因单个席位完成而关闭。协作取消和失败可原作业重试，因此仍保持开放；Agent 待输入、阻塞、失败、中断及其他未证明不可续办的状态也保持开放。启动时重扫已保存的明确完成记录以补偿终态写入后尚未关预算的崩溃窗口。

服务启动及每小时回收已关闭超过 24 小时的任务与尝试详情，owner 墓碑和发行序号仍保留，旧任务重放不能重新获得额度。墓碑数量仍有 100,000 的永久容量上限；周期回收只释放任务与尝试详情，不能解除该上限。备份/恢复须把此 sidecar 与任务数据作为同一份快照处理；若 sidecar 缺失，历史预算无法恢复。上线前已有运行的历史花费不可从有限账本重建，因此旧续跑被拒绝。

资讯 plan/write 当前同批共用持久 owner，但批次 UUID 未在发起前独立持久保存，不能承诺跨崩溃续批。`tool_text` 及其他缺少稳定 owner 的入口仍使用有界进程内预算，尚未获得跨重启保护。原有直连文字与媒体旁路亦未覆盖；上述保护只约束经过接线入口的请求输出 Token 上限，不能视为全项目费用硬上限。

预算身份传播前置改动：新 Agent 运行在启动时生成独立 UUID，传给文字适配器并写入运行元数据；续跑读取原 UUID。协作作业在入队时写入独立 UUID，所有席位共用，缺少该身份的旧作业在服务端执行前拒绝。资讯同一生成批次的 plan/write 共用 UUID；盯看、点子与工具文字请求各自独立。模型适配器无身份时使用局部匿名身份，不用可重复的展示 run ID 作为预算键。这仍是进程内计数；SQLite 账本接入前，UUID 元数据不构成跨重启额度保证。万神殿与其他未显式传入身份的直调仍仅有适配器局部匿名预算，尚未按完整任务共享。
