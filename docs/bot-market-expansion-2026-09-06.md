## 采用的具体设计

- 文稿润色：先保留事实再改变表达；正文和解释分离；默认保守保留作者语气。没有照抄不适合中文的一刀切标点禁令。
- 通话跟进：明确承诺与模糊建议分开；机器摘要不冒充逐字引语；负责人、基准日期和完成状态均必须有依据。
- 方案压力测试：按用户个人目标评估；没有证据不等于证伪；选出最影响决策的不确定性，比较低成本试验并给出可观察标准，不假装完成市场调查。
- 演示稿审阅：只覆盖提供的页面文字；先说明听众理解，再看叙事、证据和数字口径；不把相邻数字强当分母，不将预测当业绩。
- Bot 设计：单一职责、明确输入输出、缺资料处理、禁止事项与三个合成验收用例；生成可编辑规则草稿，用户确认保存才创建。

原模板的邮箱、日历、录音、CRM、文档平台、图片和幻灯片渲染、自动文件写入、pstack 及周期任务均未移植。五个新 Bot 都只接收当前任务的文字，运行时工具关闭、长期记忆关闭；写规则不能扩大这些权限。用户仍需在模型服务配置可用连接。

[Researchy](https://x.ai/bot/i2hvaEONDg6_gEF5C9RlK) 暂未纳入：核对到的主要流程依赖 Grok CLI、指定模型和实时搜索，以及原作者的安装与登录环境。把它缩成粘贴资料分析却称为实时研究会造成误导；本轮不重新安装已移除的开发引擎。

## 使用上的改进

1. 每个模板有专属资料提纲；“用合成示例试一试”是显式动作，不自动填入，也不覆盖已有材料。正常任务目标不带入示例预算、日期或页数。
2. “我的 Bot”可以直接点击使用，预选角色；已停用 Bot 不能直接启动。个人编辑的规则不会被再次添加模板覆盖。
3. 交付内容可以单独复制正文，完整复制保留来源；支持本机导出 UTF-8 文本。导出只读取当前用户成功交付的任务，不包含连接指纹或其他任务。
4. Bot 设计结果新增“审阅并创建 Bot”：仅从成功任务且冻结来源为 bot-designer 的结果提取名称与规则；字段缺失、重复、过长均拒绝，不默默截断。打开编辑框不创建、不运行，点击保存才创建普通用户 Bot，不能伪造市场来源或权限。
5. 沿用既有字体、颜色、输入→交付卡片和响应式布局；没有引入新视觉框架或增大客户端依赖。

## 验证与限制

- 类型检查通过。
- 全量回归 498 项：497 通过、0 失败、1 原有跳过。
- 八模板均经过模拟模型执行，验证仅共享当前材料、关闭工具及记忆、专职回执后由主助理交付。
- HTTP 验证覆盖八模板导入、重复导入、个人编辑保留、重启持久化、不因添加产生模型调用或任务；错误版本和未知 ID 拒绝。
- 新文本交付辅助测试覆盖草稿来源/成功状态、超长与重复字段、无损纯文本、资料不覆盖；HTTP 导出覆盖附件类型、无缓存、未完成与缺失任务拒绝。
- 实际浏览器验证：1440px 桌面与 390px 窄窗口、搜索和分类、资料提纲、显式示例、单项复制、审阅后创建、直接使用和真实文件下载。自动化 download 命令曾取消；专用会话普通点击下载成功，文件与 HTTP 输出哈希一致。详见工作区 outputs/bot-market-ux-20260906/report.md。
- **新增五个 Bot 尚未完成真实模型内容质量验收。** 本轮提出的约 10 次付费调用授权尚未收到回复，未擅自追加这些测试。模拟通过不意味着模型一定会保留每个事实；来源格式检查也不等于内容真实。
- 未验证新源码在其他电脑或新便携包内的运行。本轮明确不打包。Grok 原市场模板在本轮是公开设计核对，不是五个原 Bot 的执行实测。

## 建议先试的顺序

先用文稿润色处理一小段不敏感原稿，再用通话跟进处理一份文字摘要。希望定制自己的流程时，使用 Bot 设计助理生成草稿，审阅后保存，再拿正常、缺资料和越权三个用例逐一验收。
