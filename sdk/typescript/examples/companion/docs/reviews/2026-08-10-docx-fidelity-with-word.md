# DOCX 文字修改保真性验证（Microsoft Word 实机）

日期：2026-08-10
验证对象：`office-docx-text-edit.ts` 的段落级文字补丁路径
工具：`scripts/docx-fidelity/Test-DocxFidelity.ps1`

## 为什么需要这份记录

结构检查（`office-validation.ts`）只能证明 OOXML 包没坏。它无法回答两个真正决定
用户体验的问题：Word 打开这个文件时会不会弹"发现无法读取的内容"，以及没被改动的
内容格式是否真的一个字符都没变。这两个问题只有真实 Word 能回答。

文件页把某个格式标为"可编辑"之前，必须先有这份证据。

## 方法

1. **样本由真实 Word 生成**（`New-DocxCorpus.ps1`）。手工拼的 OOXML 只覆盖我们
   自己想到的结构；Word 实际写出的文件包含样式继承、主题、字体回退、rsid、
   latent styles 等大量不会主动构造的部件。保真性只有对着真实文件才有意义。
2. **用引擎各改一个段落**（`sdk/typescript/scripts/docx-fidelity-cli.ts`）。
   改的是段落前缀而非整段替换，以便同时检验补丁只重写差异部分。
3. **用真实 Word 打开产物，且 `OpenAndRepair` 传 `False`。** 这一点是关键：
   默认情况下 Word 会静默修复损坏文件，验证就失去意义；关掉之后文件有问题
   Word 直接抛错。
4. **逐字符比对格式签名。** 对每个未改动段落，按字符采样
   加粗／斜体／下划线／颜色／字号／字体，行程压缩后要求与原文完全一致。
5. **比对文档级要素数量**：表格、批注、脚注、修订、域、内嵌图形、页眉页脚文字。

## 样本

| 文件 | 覆盖内容 |
| --- | --- |
| `01-inline-formats.docx` | 中英混排，单段落内三种行内格式（常规／加粗／红色大字） |
| `02-headings-list-table.docx` | 标题样式、项目符号列表、3×3 带边框表格 |
| `03-header-footer-footnote.docx` | 页眉、页脚、页码域、脚注 |
| `04-comments-revisions.docx` | 批注、开启修订后新增的段落 |
| `05-long-chinese.docx` | 60 段中文正文，混入英文与数字 |
| `06-empty-paragraphs.docx` | 空段落与制表符（验证不会因为过滤空段而错位） |

## 结果

2026-08-10 运行，Word 16.0，**6 / 6 全部通过**：

- 6 份产物全部被 Word 在禁止修复的模式下正常打开；
- 表格、批注、脚注、修订、域、页眉页脚数量与原文一致——批注与修订在
  `04` 中确认存活，页眉页脚与脚注在 `03` 中确认存活；
- 未改动段落文字逐段一致（`05` 中为 59 段）；
- 未改动段落的逐字符格式签名完全一致。

对照：已冻结的 `office-structured-edit.ts` 在同样的单段落三格式样本上会把
加粗与红色大字的 run 归属压平（见 `tests/unit/office-docx-text-edit.test.ts`
中的对比用例）。

## 复现

```
pwsh -File scripts/docx-fidelity/Test-DocxFidelity.ps1
```

需要本机安装 Microsoft Word。退出码：0 全部通过，1 有失败项，2 环境不满足。
样本每次重新生成，不入库。

CI 不跑这项检查——CI 机器上没有 Word。它是发布前的人工检查项，
格式能力标注变更时必须重跑。

## 这份证据不覆盖什么

- 只验证了**文字修改**。增删段落、改样式、改页眉页脚批注修订都不在当前能力范围内。
- 没有验证 WPS 与 LibreOffice（本机未安装）。对外声明"可编辑"前应补上，
  或明确只声明 Microsoft Word 兼容。
- 没有覆盖加密文档、宏文档、超大文档（当前单文件上限 8 MB）、
  以及由 WPS／LibreOffice 创建的样本。
- 图片、图表、公式、文本框虽在结构上原样透传，但样本中未包含，尚无实机证据。
