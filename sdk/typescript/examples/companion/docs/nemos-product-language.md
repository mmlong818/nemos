# Nemos 产品命名准则

> 目标：让第一次使用 Nemos 的人不需要学习术语，也能一眼知道入口能做什么。

## 核心判断

Nemos 与传统软件的区别，不靠陌生名称体现，而靠三件事体现：

1. 用户只需要说清目标，不必先找到正确工具。
2. Nemos 会结合少量个人习惯完成任务。
3. 结果不是一次性回答，而是可以继续修改和下载的文件。

## 命名规则

- 主名称使用“动作＋对象”，例如“做 PPT”“整理会议纪要”。
- 主名称尽量控制在 2—8 个汉字；专业解释放在副标题。
- 优先使用用户已经认识的文件名称，再补充格式，例如“可编辑 PPT”“Word 文档”。
- “能力”可以作为一级入口；具体能力仍使用“动作＋对象”。不在普通用户界面中使用“产物、运行、扩展、契约、组件、模式”等内部词。
- 流程统一命名为“开始、进行中、已完成”，对应用户对任务进度的自然理解。
- 记忆只在与当前结果有关时出现，统一表达为“按我的习惯生成”。

## 信息层级

每一项都保持三层：

1. **名称**：用户现在能做什么。
2. **一句说明**：Nemos 会怎么做。
3. **结果格式**：最终能拿到什么文件。

内部仍可保留稳定的能力 ID、执行状态和格式代码，但不直接暴露给普通用户。
