# 小丑鱼 Capability OS Design

## 目标

小丑鱼的目标不是做一个只会聊天、只会几个固定工具的助手，而是做一个可以逐步解决用户所有事务的个人 AI 工具系统。

这个目标天然意味着需求方向会非常多：交易、出行、订酒店、找餐馆、写文档、做研究、整理资料、生成图片、管理日程、处理文件、监控信息、联系外部服务、维护长期项目。更多需求现在还无法枚举，所以系统设计不能依赖“预先想全功能列表”。它必须允许未知需求进入系统，再由系统判断：已有能力能不能解决、缺什么数据源或工具、是否要生成新技能、是否要接入新连接器、是否需要用户确认。

小丑鱼的客户端只负责陪伴体验、角色展示、聊天和产物入口。真正做事的部分放在本机后台能力层：角色可以调用专有工具、形成可复用技能、按时间或聊天轮次执行任务，并把结果保存为 Markdown、HTML、JSON、Word、PDF、Excel 或 PowerPoint。

这套设计保留 小丑鱼 原有的关系和记忆核心，不替换成第三方记忆系统。外部项目只作为交付形态和能力组织方式参考。

Agent 执行层的具体边界、已落地代码和后续迁移顺序见 [`agent-runtime-design.md`](./agent-runtime-design.md)。

## 核心原则

1. **陪伴核心保持小**：角色、关系、熟悉度、记忆仍由 小丑鱼 管。
2. **能力放在后台**：客户端不直接持有业务能力，只展示状态、触发任务、打开产物。
3. **技能可审查**：自学能力不只是一段 prompt，必须落盘为 `SKILL.md`，可查看、可改进、可归档。
4. **来源先于答案**：涉及价格、余票、房态、营业时间、菜单、行情等实时信息时，先判断可靠来源类型，再回答。
5. **结果必须可交付**：任务完成标准是角色在聊天里交付结论，并保存一个非空产物。
6. **未知需求优先被建模**：遇到新事务时，系统先输出“需求类型、可用能力、缺口、下一步接入方案”，而不是简单失败。
7. **能力可以无限扩展**：新能力优先通过技能、连接器、插件、MCP 或后台 worker 增加，不膨胀陪伴核心。

## 无限需求处理循环

所有新事务都走同一个循环：

1. **理解需求**：识别目标、限制条件、交付格式、时效要求、是否涉及钱/时间/账号/隐私。
2. **匹配已有能力**：从技能库、工具注册表、来源连接器和历史产物中找可用方案。
3. **判断能力缺口**：如果不能直接完成，明确缺的是数据源、账号、API、网页自动化、文件权限、外部确认，还是领域流程。
4. **先交付可交付部分**：能做的先做；不能确认的明确标注，不伪造结果。
5. **沉淀能力**：把成功流程写成技能，把重复出现的数据源抽成连接器，把复杂任务交给后台 worker。
6. **更新路线图**：如果这是一个新领域，把它作为能力系统的新里程碑，而不是临时补丁。

## 架构分层

### 1. 客户端层

- 桌面客户端 / WebView
- 聊天区、角色列表、能力与任务面板
- 展示任务进度、工具可用性、来源连接器、产物列表

### 2. Companion 服务层

- `server.ts`
- 提供聊天、能力、Agent 运行记录、后台任务、扩展注册和多 Agent 编排接口
- 管理 LLM key、运行时目录、本机备份、任务轮询

### 3. Agent 运行时

- `src/agent/runtime.ts` 统一模型—工具循环、取消、预算、上下文接力和事件
- `src/agent/run-store.ts` 保存可恢复的运行记录与脱敏审计
- 所有写工具默认拒绝，必须由授权策略放行

### 4. 能力运行时

- `capabilities.ts`
- 管理能力、任务、产物、定时/轮次触发
- 构造任务执行 prompt
- 把任务结果保存到本机 artifacts
- 把生成/自学能力写成技能文件

### 5. 工具注册表

- `capability-tools.ts`
- 负责记录后台工具、工具集、可用性、依赖项
- 当前可执行：通用网页搜索、网页读取、视觉、OCR、语音、文档处理、来源发现，以及港股公告与行情快照
- 动车、航班、酒店、餐馆条目只返回来源分类和核验边界；产品明确不接实时查询和预订适配器
- 港股适配器在这一层读取关注列表、港交所公告和带时间戳的第三方行情快照

### 6. 来源连接器

- `source-connectors.ts`
- 负责把用户任务映射到可靠来源类型
- 当前覆盖：港股/市场真实只读适配器；动车/火车、航班、酒店、餐馆核验边界；新领域来源发现
- 港股执行器已接入；出行和餐旅保持核验规则，不列入后续开发范围

### 7. 需求识别与能力匹配

- 输入：用户自然语言、文件、图片、语音、网页、历史任务
- 输出：需求类型、已有能力匹配、能力缺口、可交付结果、建议新增能力
- 目标：任何需求都能进入系统，不需要用户先学习“怎么配置能力”

### 8. 技能库

- 数据目录：`<CLOWNFISH_HOME>/capabilities/skills`
- 每个生成或自学能力都有一个 `SKILL.md`
- 同目录 `manifest.json` 保存机器可验证的版本、权限、激活条件和工具声明
- `.usage.json` 记录能力来源、使用次数、状态、最后使用时间
- 已有审查、重复检测、归档建议、归档和恢复；下一步增加固定/停用状态以及基于成功证据的技能改进

### 9. 扩展、后台 Worker 与编排

- 短任务：由当前角色直接执行
- 长任务：进入持久后台队列，完成后由角色交付；刷新或重启不会丢失状态
- 复杂任务：由受控 Orchestrator 拆成有界子任务，只共享产物引用
- 扩展：Skill、MCP 与 Agent App 通过同一 manifest 契约安装、启停、审查和升级
- 新领域：先生成连接器方案，再接入工具或插件
- 高风险任务：必须有用户确认，例如交易、付款、发消息、修改重要文件、提交外部表单

## 当前进度

路线图状态由 capability-roadmap.ts 维护，客户端通过 /api/capabilities/roadmap 读取。本节按代码和测试重新核验于 2026-08-04。

状态口径：

- done：已有真实执行链路并通过测试，不以占位工具、提示词或来源说明代替。
- doing：已有可运行部分，但尚未达到本阶段验收标准。
- next：已有明确接口和验收标准，尚未实现真实执行器。
- later：保留方向，当前没有进入实施。

当前完成：

- 独立客户端、本机服务、流式任务执行和可下载产物
- 能力、任务、产物与 Skills 管理
- 需求识别、能力匹配、缺口报告和连接器方案生成
- 自学能力生成 SKILL.md，以及技能审查、重复检测、归档和恢复
- 会话相关任务、能力、需求记录和产物的本机检索
- 来源分类、核验规则和产物中的确认状态展示
- 通用 Agent Runtime、工具调度、持久运行记录和脱敏审计
- 持久后台任务队列、取消、超时、租约恢复、幂等触发、人工重试保护、服务端交付确认和客户端 `jobId` 去重
- Skill、MCP、Agent App 扩展清单、官方 stdio provider、按请求加载和运行级进程隔离
- MCP 短期凭证代理：真实 Key 不进入第三方进程，地址、方法和请求头受清单约束
- Node MCP 权限沙箱：文件读取/写入路径由清单限定，子进程和 Worker 一律禁止；网络必须声明为拒绝或直连
- Windows 非 Node MCP 沙箱：Python 与直接可执行扩展进入 LPAC，文件、子进程、外网和本机回环均按清单限制；便携包内置校验过的 Python 3.14.6 运行时
- 可执行扩展信任状态：未确认的旧扩展默认阻止，明确允许未沙箱运行的决定会持久审计
- 有硬 Token 预算、并发、取消、失败隔离、质量检查、Token 统计和费用估算的多 Agent 编排
- 客户端 Agent 运行中心，以及明确用户写操作的统一审计

本轮已完成：

- 港股/市场真实只读资料适配器
- 技能固定、停用、陈旧状态与基于证据的改进闭环

明确排除：

- 动车、航班、酒店和餐馆的实时查询、库存与预订适配器；相关请求只说明可靠来源类型和人工核验边界。
- 通用网页搜索可以提供线索，但不等于票务库存、酒店房态或餐馆订座的结构化实时来源。
- MCP 已能真实连接、发现和调用外部 stdio 工具。Node MCP 使用独立 Node 26.5.0 权限沙箱并支持短期凭证代理；Python 与直接可执行 MCP 使用 Windows LPAC，禁网时连本机回环也拒绝。需要凭证代理的扩展不能使用 LPAC，应走 Node 沙箱或内置连接器。

## 阶段验收标准

### P0 能力底座

完成标准：

- 客户端能显示能力、任务、产物
- 任务运行有流式状态
- 结果能保存为文件
- 生成/自学能力能写入 `SKILL.md`
- `/api/capabilities/tools` 能返回工具和来源状态

状态：已完成。

### P1 真实来源

完成标准：

- 港股任务能读取关注列表、公告/行情来源和盘前/盘后模板
- 出行任务能区分时刻表、价格、余票、延误等数据来源
- 酒店/餐馆任务能区分稳定信息和实时信息
- 产物中明确标注已确认、待核验、不可确认

状态：已完成。港股可读取本机关注列表、港交所官方公告和带时间戳的第三方行情快照；出行与餐旅实时适配器按产品决定排除，仍保留核验边界。

### P2 自学习维护

完成标准：

- 技能有 active/stale/archived/pinned 状态
- 高频成功流程能改进技能文件
- 长期不用或重复技能能被归档
- 角色能搜索历史任务和产物

状态：部分完成。技能审查、归档、恢复和本机检索已完成；固定/停用状态和基于结果证据的自动改进尚未完成。

### P3 后台工作和插件化

完成标准：

- 复杂任务进入 worker 队列
- 聊天不中断，完成后由角色交付
- 搜索、浏览器、行情、票务、酒店、餐馆等能力可以通过插件/连接器扩展

状态：基础设施已完成。MCP stdio 传输、运行隔离、凭证代理、可执行扩展默认拒绝策略，以及 Node 与 Windows LPAC 两条沙箱路径已经通过真实子进程测试。便携客户端保留 Node 24 主服务，同时附带经官方发布包 SHA-256 校验的 Node 26.5.0、Python 3.14.6 和 AppContainer 宿主；运行时缺失、版本不符或无法启动时失败关闭。港股只读 provider 已内置，票务、酒店和餐馆 provider 不在产品计划内。
