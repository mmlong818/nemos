# Nemos 当前产品设计简报

状态：Design v0.1
日期：2026-08-04
范围：先设计 Nemos 当前产品，再筛选需要补入的能力；不包含生产功能实现

## 1. 设计判断

Nemos 不是能力市场，也不是把所有工具塞进聊天框的通用助手。它的核心是：**一个有关系和记忆的本机 AI，既能陪伴，也能持续完成工作并交付可继续使用的产物。**

当前界面最需要解决的不是换配色，而是重新分层：聊天负责关系和即时交流；能力中心负责选择目标、准备输入和启动任务；自动任务负责重复执行；产物库负责预览、修改、比较和导出；运行记录负责解释进度、失败与恢复；记忆设置只管理用户真正关心的长期偏好。

## 2. 当前界面审视

实际页面中，“能力与任务”弹窗同时容纳 Agent 运行、扩展、Skills、能力列表、本机检索、任务工作台、新增能力、安装、常规任务和产物。结果是：

1. 普通用户需要在开发和运维信息中寻找“我现在要完成什么”。
2. 能力、任务、运行和产物处在同一视觉层级，主操作不明确。
3. Markdown、HTML、文档稿、JSON 被当作普通下拉选项，但 PPT、正式文档、报告网页实际上需要完全不同的版式流程。
4. 来源地址、安装方式和内部类型进入普通界面，不符合 Nemos 原生能力的呈现边界。
5. 紫粉渐变、发光阴影、圆角卡片大量重复，削弱内容层级，也没有表达“记忆和长期协作”的独特性。

## 3. 产品结构

全局导航固定为 7 个目的明确的入口：

```text
聊天       与角色交流、继续任务、接收完成通知
能力中心   选择目标、准备输入、直接运行
自动任务   管理定时与条件触发
产物库     预览、修改、比较、导出和复用
运行记录   查看进度、审批、失败、恢复和成本
记忆       查看与修正个人信息和交付习惯
设置       模型、文件、连接、备份和安全
```

“Skills、MCP、扩展清单、安装路径、上游地址”不进入普通产品导航。需要维护时放入受保护的本机开发控制台，并使用 Nemos 自有对象和字段。

## 4. 能力中心首版

能力中心采用三栏工作台，而不是卡片墙：

- 左栏：按结果分类和最近使用筛选。
- 中栏：能力列表，显示一句话结果、可用状态和产物类型。
- 右栏：所需输入、产物预览、版式选择、记忆偏好和开始动作。

首屏默认选择最近使用的能力。用户也可以直接输入目标，由 Nemos 匹配现有能力；匹配不到时先形成“能力缺口”，不在产品界面暴露能力是如何获得的。

## 5. 产物不是文件后缀

产物分成 5 个家族，每个家族有自己的设计规则：

| 产物家族 | 首版格式 | 必须解决的问题 |
|---|---|---|
| 快速内容 | MD、TXT | 信息层级、可复制、可继续对话 |
| 正式文档 | DOCX、PDF | 标题体系、页眉页脚、分页、表格、引用、打印 |
| 演示文稿 | PPTX、PDF、HTML 演示 | 故事线、页面节奏、母版、16:9、逐页审视、演讲备注 |
| 网页报告 | HTML、PDF | 响应式、导航、数据图表、打印、离线可用 |
| 结构数据 | JSON、CSV | 字段契约、校验、编码、导入兼容性 |

因此“制作演示”不是把 Markdown 转成 `.pptx`。它需要先确定受众、场景、核心结论和页面数量，再产生故事线、页面清单和版式系统，逐页生成、检查溢出和一致性，最后导出。正式文档和网页报告也走各自的排版链路。

## 6. 首轮能力筛选

本轮不按外部项目的功能表照搬，只按 Nemos 当前用户旅程判断缺口。

| 能力方向 | 当前基础 | 产品缺口 | 优先级 |
|---|---|---|---|
| 信息速览、方案研判、事实核验 | 已有能力与运行基础 | 需要统一输入、证据状态和产物模板 | P0 |
| 正式文稿 | 已有 Markdown 文档稿 | 缺真实 DOCX/PDF 排版与预览 | P0 |
| 制作演示 | 尚无完整能力 | 缺故事线、母版、逐页布局、预览和 PPTX/PDF 导出 | P0 |
| 网页呈现 | 已有 HTML 报告 | 缺稳定设计系统、响应式与打印验证 | P1 |
| 数据图表 | 有表格内容，无统一视觉层 | 缺图表选择、精确渲染和版面嵌入 | P1 |
| 图像、视频与复杂创意生成 | 有零散工具基础 | 尚未证明是当前高频主路径 | Later |

首批新增重点因此是：**制作演示、正式文稿排版、网页报告版式、数据图表**。它们共享“产物工作台”，但不共享同一套页面模板。

## 7. 记忆系统的作用

记忆只轻量影响交付，不接管产品视觉系统。每次最多应用 4 项：

1. 习惯：先结论还是先过程、默认详略。
2. 文笔：语言、语气、句子长短、术语密度。
3. 排版：标题层级、表格使用、摘要与目录。
4. 格式：常用 DOCX、PPTX、PDF、HTML 或 Markdown。

PPT 的品牌色、母版、客户模板等属于“当前项目样式”，不是从一次使用中自动学出的全局记忆。当前任务明确要求永远覆盖长期习惯。

## 8. 视觉系统

Nemos 保留柔和、有人情味的底色，但去掉大面积紫粉渐变和发光装饰：

- 背景：暖纸色 `#F4F0E8`，主要表面 `#FFFCF7`。
- 文字：墨色 `#20221F`，次级文字 `#686B64`。
- 品牌强调：莓红 `#B33F72`，只用于当前状态和主操作。
- 状态成功：松绿色 `#2F6A57`；警告与错误只承载真实状态。
- 标题可使用克制的衬线字体，正文和控件使用清晰的中文无衬线字体。
- 4px 间距基准，正文 14—16px，可点击区域至少 44px。
- 统一使用 1.8px 线性图标；状态不能只靠颜色表达。
- 阴影只说明层级，卡片优先用分隔、留白和背景差异组织。

页面记忆点是右侧“产物舞台”：用户选能力时立即看见将要得到的版式，而不是只看一段能力说明。

## 9. 原型范围

本轮高保真原型覆盖两个状态：

1. 能力中心：以“制作演示”为例，展示能力选择、版式预览、输入要求、输出格式和轻量记忆偏好。
2. 产物工作台：展示幻灯片缩略图、当前页预览、版式信息、应用过的偏好和导出动作。

原型使用脱敏示例数据，不连接生产接口，不包含安装、来源、上游名称或外部能力标识。

## 10. 设计验收

1. 用户在 5 秒内能找到“制作演示”并知道会得到什么。
2. 能力、自动任务、运行记录和产物不再混在一个弹窗中。
3. PPT、DOCX、HTML 不再只是同一个格式下拉框。
4. “使用我的习惯”存在但不抢占主流程，每次最多应用 4 项。
5. 普通界面不显示安装、路径、来源地址、原始类型或内部提示词。
6. 桌面端可并排比较能力与产物；窄屏仍能完成选择和启动。
7. 所有主操作有清晰焦点状态，正文和控件满足基本对比度与触控尺寸。
