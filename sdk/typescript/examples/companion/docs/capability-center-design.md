# 小丑鱼能力页产品规范

状态：当前实现说明
更新：2026-08-06

本文描述 **/capabilities** 的现有用户流程和验收边界。界面与接口变化后，应同时更新本文和对应测试。

## 1. 页面任务

能力页只解决一件事：把“我想完成什么”变成可以运行、跟踪和交付的任务。

它不是工具市场，也不要求用户先理解能力名称。

## 2. 两条入口

### 说目标

用户填写任务目标，点击“自动选择并继续”。系统选择匹配的公开能力并进入任务表单。

### 直接选择

用户点击能力卡片后直接进入任务表单。不得再出现“准备能力”“添加能力”或第二次选择能力的中间步骤。

两条入口最终使用相同的任务结构、运行队列和结果页。

## 3. 页面结构

顶部状态导航：

- 开始
- 进行中
- 已完成
- 文件

开始页从上到下为：

1. 任务目标输入；
2. 自动选择按钮；
3. 常用能力；
4. 全部能力入口。

桌面端保留稳定左侧主导航；小屏改为紧凑导航，不能因滚动条、选中态或图标宽度发生横向跳动。

## 4. 任务表单

表单只保留影响结果的字段：

- 任务要求；
- 参考材料；
- 结果形式；
- 是否使用长期习惯；
- 必要的高级设置。

主按钮应直接表达动作，例如“开始生成”或“开始处理”。校验提示放在字段附近，不单独占用右侧检查栏。

## 5. 运行

任务提交后进入持久队列：

- 排队、运行、成功、失败和取消均有明确状态；
- 支持实时进度；
- 用户可以取消仍在排队或运行的任务；
- 失败或取消的任务可以受保护地重试；
- 刷新页面后仍能继续查看。

运行状态以服务端任务和运行记录为准，界面不得伪造完成。

## 6. 结果

完成结果应提供：

- 当前页面内预览；
- 下载；
- 返回原对话时的交付提示；
- 结果历史；
- 必要的格式或版面警告。

Office 文件处理在 **/office** 页内完成，不应为同一任务再跳到能力页。

## 7. 历史

- “进行中”显示未结束任务；
- “已完成”显示成功、失败和取消的历史；
- “文件”显示可预览或下载的交付物；
- 再次使用历史能力会新建任务，不覆盖旧记录；
- 删除任务与删除交付物是不同动作。

## 8. 记忆

任务可使用 **preferences** 或 **off** 两种记忆模式：

- preferences：只召回交付偏好；
- off：不注入用户记忆。

偏好只影响习惯、文笔、排版和格式，不改变事实核验、安全规则或当前任务要求。详细规则见 [能力与记忆实现](capability-center-memory-design.md)。

## 9. 能力可见性

普通用户只看到可直接使用的公开能力。内部辅助能力、适配器、迁移入口和开发者工具不进入普通能力列表。

实时动车、航班、酒店和餐馆查询不在当前范围内，不显示为可用能力。

## 10. 验收

1. 新用户不创建项目也能启动第一个任务。
2. 直接选择能力后立即进入任务表单。
3. 任务目标、结果形式和材料在提交前可见。
4. 运行刷新后仍可追踪。
5. 结果可以预览和下载。
6. 失败、取消和重试状态真实一致。
7. 左侧导航和顶部状态切换不抖动。
