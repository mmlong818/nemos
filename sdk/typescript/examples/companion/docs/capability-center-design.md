# 小丑鱼 能力中心设计稿

状态：Design v0.6
日期：2026-08-04
本轮范围：先完成当前 小丑鱼 产品设计，再筛选能力缺口；包含能力净化规范与实施边界，不包含生产功能实现

## 1. 产品决定

小丑鱼 将能力系统设计成独立的「能力中心」。聊天只是其中一个调用入口，用户也可以在能力中心直接选择、配置和运行能力。

所有进入 小丑鱼 的能力必须成为 **小丑鱼 原生能力**：统一命名、统一交互、统一数据结构、统一运行状态，不向产品用户或普通开发者暴露能力血缘。

能力中心需要让用户快速回答：

1. 小丑鱼 能完成什么结果？
2. 当前是否可以运行？
3. 需要提供什么输入？
4. 会输出什么文件或结果？
5. 运行到哪一步，结果保存在哪里？

### 设计顺序

本项目不先照着任何外部能力列表做功能合并。正确顺序是：

```text
审视当前 小丑鱼 用户路径
→ 设计聊天、能力、任务、产物、运行与记忆的产品分工
→ 用真实任务验证缺口
→ 只选择 小丑鱼 确实需要的能力方向
→ 抽象成 小丑鱼 行为需求
→ 独立实现、测试和发布
```

版式产物是当前明确缺口。PPT、正式文档、网页报告和数据图表不能只作为“输出格式”处理，它们分别需要故事线、分页、母版、响应式、图表选择和视觉检查。

当前产品设计总简报见 [`clownfish-product-design-brief.md`](./clownfish-product-design-brief.md)，可交互原型见 [`../design-demos/clownfish-capability-center-v2.html`](../design-demos/clownfish-capability-center-v2.html)。

## 2. 新增约束：能力血缘不可见

### 目标

以下内容不得出现在产品界面、公开接口、运行日志、普通开发文档、测试名称或发布包中：

- 原能力名称、原始标识符和原分类；
- 原始描述、原始提示词及其特征性表达；
- 原站点、仓库、作者、供应方、链接和文件路径；
- 原格式名称、导入方式和安装记录；
- 可反推出原能力的特殊字段、示例、默认文案或测试夹具；
- “内置、搬运、安装、自学习”等血缘标签。

对外只出现 小丑鱼 自己的能力名称、能力契约和运行语言。

### 不能通过简单改名完成

只修改标题和删除链接仍会在 prompt、变量名、ID、测试、迁移代码和 Git 历史中留下痕迹。正确路径是洁净重构：

```text
私有输入
→ 许可证与使用边界检查
→ 只提取抽象行为需求
→ 用 小丑鱼 语言重新设计能力契约
→ 独立重写执行说明与测试
→ 生成净化能力包
→ 进入产品仓库和运行时
```

普通开发者只接触“抽象行为需求”之后的内容，不接触原始材料。

### 合规边界

- 如果某项材料的许可证要求向接收者公开来源或署名，则不能通过技术手段隐藏。
- 这类能力要么排除，要么基于独立需求说明重新实现，不能直接复制后删除署名。
- 必要的合规记录放在产品仓库之外，由发布负责人单独保管；不进入 UI、API、日志或普通开发文档。
- 已经获得原始仓库或历史版本的人员无法通过代码修改“消除既有认知”，只能阻止后续继续暴露。

## 3. 能力血缘与事实证据分开

本设计默认隐藏的是 **能力从哪里来**，而不是隐藏任务事实的证据。

例如，市场、出行或预订结果仍需要显示查询时间、事实状态和是否经过实时核验；否则用户会误把推断当成实时事实。界面只需说明“已核验 / 待核验 / 无法确认”，不需要展示能力本身的上游来源。

## 4. 需求简报

### 背景

现有聊天页面同时承担能力发现、任务配置、运行监控和产物展示，复杂任务缺少独立工作空间。能力对象的命名和结构也不统一，无法形成完整的 小丑鱼 产品语言。

### 目标用户

- 主要用户：通过 小丑鱼 完成研究、文档、整理、规划和自动任务的普通用户。
- 次要用户：维护能力、配置运行环境和查看审计状态的高级用户。

### 核心问题

- 能力入口受聊天界面限制，文件、表单、预检和长任务状态难以承载。
- 用户无法快速判断一个能力是真正可运行、需要配置，还是只能提供辅助方案。
- 运行、审批、失败、重试和产物之间缺少连续视图。
- 现有能力缺乏统一的 小丑鱼 命名、行为契约和可见字段边界。

### 预期价值

- 用户不依赖聊天也能直接使用 小丑鱼 能力。
- 所有能力呈现为同一产品体系，无法从界面和接口识别其历史血缘。
- 每项能力都明确显示输入、输出、依赖、事实新鲜度和风险边界。
- 运行结果统一进入产物库，并能回到对应任务和运行记录。

## 5. 小丑鱼 原生能力方向

当前能力方向采用结果导向的 小丑鱼 命名，不使用任何原始名称或血缘分类。这里是产品假设，不是待导入清单；最终范围由用户路径、真实运行能力和产物质量决定。

| 分类 | 小丑鱼 能力 |
|---|---|
| 文稿和演示 | 做 PPT、写正式文档、做网页报告 |
| 研究和判断 | 深入研究一个问题、比较方案并给建议、梳理复杂问题 |
| 产品和业务 | 设计产品方案、推进商务合作、评估商业机会 |
| 会议和跟进 | 整理会议纪要 |
| 常用流程 | 保存成常用流程 |

“做 PPT”和“深入研究一个问题”增强已有入口；需要多轮成果、长期状态或专用编辑器的能力使用独立工作台。完整边界见 [clownfish-capability-map.md](./clownfish-capability-map.md)。

### 命名规则

- 名称描述结果，不描述底层技术或供应方。
- 使用 2—6 个中文字符，避免特殊品牌词和行业黑话。
- 说明文案只描述“输入什么、得到什么、有什么限制”。
- 对外 ID 使用随机稳定标识，不使用可读的旧名称映射。

## 6. 统一领域模型

能力中心包含 5 类对象，但不把它们放在同一层级：

```text
能力
  ├─ 依赖运行组件
  ├─ 创建一次运行
  ├─ 保存为自动任务
  └─ 生成产物

新需求 ──匹配/生成──> 能力
健康检查 ──维护──> 能力状态
```

产品用语统一为：

- `能力`：用户选择的结果模板；
- `运行组件`：模型、搜索、视觉、文件处理和数据连接；
- `自动任务`：按时间或条件重复运行；
- `任务历史`：一次执行的目标、状态、时间和结果入口；
- `文件`：可预览、下载、继续修改并保留版本的结果；
- `记忆`：从任务中提炼、经过确认后长期生效的少量习惯。

## 7. 信息架构

### 全局导航

```text
聊天
能力
自动
文件
历史
记忆
设置
```

### 能力中心内部

- **能力库**：先接收用户目标并自动匹配；常用能力只作为快捷入口，“查看全部”留给明确知道能力名称的用户。
- **运行环境**：查看组件、账号、权限和连接状态。
- **新建能力**：通过 小丑鱼 能力模板创建或导入已净化的能力包。
- **能力维护**：查看异常、重复、陈旧和建议归档状态。

所有血缘字段都不参与筛选或展示。

## 8. 能力库首屏线框

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 直接说，你想完成什么？                                                     │
│ 不用先找能力，小丑鱼 会选择合适的做法。                                     │
│ [例如：给管理层做一份 12 页的项目汇报……                         →]       │
├──────────────────────────────┬─────────────────────────────────────────────┤
│ 常用能力       [查看全部 11项]│ 已安排的能力 / 当前预览                    │
│                              │                                             │
│ 做 PPT                       │ 做 PPT                                      │
│ 写正式文档                   │ 需要、会得到、怎么完成、需要注意            │
│ 深入研究一个问题             │                                             │
│ 梳理复杂问题                 │ [准备本次任务]                              │
│ 设计产品方案                 │ 目标 / 材料 / 本次使用的习惯                │
│ 整理会议纪要                 │                                             │
└──────────────────────────────┴─────────────────────────────────────────────┘
```

首屏主操作是描述目标，能力匹配在提交后自动发生。紧凑列表只展示 6 个常用快捷入口；用户点快捷入口后直接进入材料准备，不再经过“查找—分类—查看详情—再开始”的流程。

## 9. 能力详情

每项能力使用统一的“能力契约”：

1. **能完成什么**：3—5 个结果示例。
2. **需要什么**：必填输入、支持文件和用户选择。
3. **会得到什么**：产物类型、格式和是否可编辑。
4. **运行条件**：组件、账号、网络、审批和实时性状态。
5. **能力边界**：不能确认或不会自动执行的事项。
6. **最近运行**：状态、耗时、触发方式、产物和重试。

不展示原始 prompt、历史名称、来源字段、原文件路径或创建方式。

## 10. 核心流程

### 直接运行

```text
描述目标 / 点常用入口 → 自动匹配能力 → 填写输入或上传文件 → 运行预检
                       → 确认风险或审批 → 后台运行 → 查看进度
                       → 预览产物 → 下载 / 继续修改 / 发送到聊天
```

运行表单按照能力契约动态生成：

- 文本、链接、日期、地点等结构化字段；
- 文件拖放区，显示格式、大小和解析状态；
- 输出格式选择；
- “保存为自动任务”选项；
- 明确的动作名称，如“生成会议整理”，不使用含糊的“继续”。

### 新建能力

```text
描述目标 / 导入净化能力包
→ 生成 小丑鱼 能力契约
→ 检查输入、输出、权限和风险
→ 测试运行
→ 保存为草稿或启用
```

产品只接受符合 小丑鱼 Schema 的净化能力包。原始材料的读取与净化不在普通开发仓库中完成。

### 新需求匹配

```text
输入“我想完成什么”
→ 匹配现有能力
→ 显示匹配理由和缺失输入
→ 直接运行；或生成能力缺口
→ 用户确认后创建新的 小丑鱼 能力
```

### 结果迭代

```text
打开文件 → 查看事实状态和运行信息 → 提交修改要求
→ 产生新版本 → 切换、比较、下载
```

### 历史与恢复

历史不和能力发现混在一起。开始页只提供一个紧凑的“继续上次”，完整记录进入“历史”页。

```text
开始页“继续上次” → 恢复目标和已保存材料
历史“再次使用” → 创建新任务，原记录保持不变
历史“打开结果” → 进入对应文件
文件“查看版本” → 在当前文件内切换或比较版本
```

三类信息分开管理：

- **任务历史**保存每次运行的目标、状态、时间和结果入口，包含成功、部分完成、失败和取消。
- **文件版本**跟随文件保存，不把每次编辑展开成一条任务记录。
- **记忆影响**只保存确认后的长期习惯，不等同于原始历史；清理任务时可分别处理任务、文件和由任务产生的记忆。

## 11. 状态模型

### 能力状态

| 状态 | 含义 | 主操作 |
|---|---|---|
| 可运行 | 必要条件已满足 | 开始运行 |
| 需配置 | 缺少账号、模型或本地组件 | 去配置 |
| 辅助模式 | 可以生成方案，但不能确认实时事实 | 查看限制 |
| 暂时不可用 | 依赖离线或检查失败 | 重试检查 |
| 已归档 | 默认不参与匹配 | 恢复 |

### 运行状态

`排队中 → 运行中 → 等待审批/等待输入 → 成功/部分完成/失败/已取消`

“部分完成”单独存在，例如文档已生成，但实时事实未核验。

### 维护状态

使用“正常 / 观察 / 疑似重复 / 建议归档 / 已归档”，不显示能力是如何产生的。

## 12. 文档输入与产物

目标状态：

- 输入：TXT、MD、HTML、JSON、CSV、PDF、DOCX；图片进入图文提取；音频先转写。
- 处理：上传、类型检查、文本提取、页数/字符数提示、失败位置提示。
- 输出：MD、HTML、TXT、JSON、DOCX；只有真实转换器可用时才显示 PDF。
- 预览：文本、Markdown、HTML 内嵌预览；DOCX/PDF 提供渲染预览或下载。

现有“文档草稿”若实际是 Markdown，界面必须显示为“可编辑草稿”，不能伪装成 Word 文件。

## 13. 视觉方向

- 保留 小丑鱼 应用壳和角色体系，不建立第二套品牌。
- 暖白、浅灰和墨色为主；品牌强调色只用于当前导航和主操作。
- 状态颜色只承载语义，并配合文字或图标。
- 使用单一线性图标体系。
- 4px 间距系统，列表行 72—88px，右侧详情宽 360—420px。
- 桌面三栏；窄屏收为“分类抽屉 + 列表 + 独立详情”。
- 所有交互提供键盘焦点状态，状态不能只靠颜色表达。

页面的记忆点是统一的能力契约：**需要什么 → 怎么运行 → 得到什么 → 哪些事实仍待确认**。

## 14. 净化后的数据模型

运行时只接收 小丑鱼 自有 Schema：

```ts
interface ClownfishCapability {
  capabilityId: string;
  title: string;
  summary: string;
  category: "information" | "document" | "visual" | "planning";
  tags: string[];
  inputKinds: Array<"text" | "url" | "image" | "audio" | "file">;
  outputFormats: Array<"md" | "html" | "txt" | "json" | "csv" | "docx" | "pptx" | "pdf">;
  requiredComponentIds: string[];
  optionalComponentIds: string[];
  risk: "local" | "external-read" | "external-write";
  behaviorVersion: string;
  readiness: "ready" | "setup-required" | "assisted" | "unavailable" | "archived";
}
```

公开模型中禁止出现：

```text
source
sourceUrl
origin
provider
upstreamId
originalName
originalPrompt
importPath
repository
author
learnedKey
```

需要供应方信息才能运行的组件，由凭证代理用内部组件 ID 处理；能力目录和运行日志不返回供应方名称。

## 15. 净化实施规范

### 能力定义

- 重新编写名称、说明、执行步骤、错误文案和示例。
- 只保留通用行为要求，不复制特征性表达和结构。
- 使用全新的随机 ID、字段顺序和分类体系。
- 测试验证输入、输出和安全边界，不使用原始名称作为夹具。

### 仓库与构建

- 普通仓库只保存净化后的能力包和 小丑鱼 Schema。
- 原始材料、映射表和合规记录不进入普通仓库。
- 构建阶段验证禁止字段和禁止特征，不合格则停止发布。
- 发布包、Source Map、调试端点和错误堆栈均不得泄露私有映射。

### API 与日志

- API 采用字段白名单序列化，不直接返回内部对象。
- 审计日志只记录 小丑鱼 capabilityId、行为版本、权限和结果。
- 错误信息使用 小丑鱼 组件名称，不透传底层库或远端响应中的供应方标识。
- 文件名、缓存目录和产物元数据使用 小丑鱼 自有命名。

### 检查门禁

- 对工作树、构建产物、测试快照和文档运行特征扫描。
- 对公开 API 进行快照测试，确认不存在禁止字段。
- 对 UI、下载文件、日志和错误路径进行端到端泄漏测试。
- 由未接触原始材料的人员审查净化能力包。

## 16. 分期建议

### Phase 0：净化与合规门禁

- 确认每项能力是否允许重新实现和发布。
- 产出抽象行为需求，不复制原始表达。
- 完成 小丑鱼 原生名称、ID、能力契约和测试重写。
- 清理当前工作树中的显式血缘字段和特征。
- 增加仓库、API、日志和构建产物扫描。
- 决定是否需要新建洁净仓库或处理 Git 历史。

### Phase 1：独立能力中心

- 新增能力中心和全局导航入口。
- 能力目录、搜索、分类、详情、状态和直接运行。
- 运行环境状态页。
- 复用净化后的运行、审批、任务和产物接口。

### Phase 2：文档工作台

- 通用文件上传与解析。
- 真实 DOCX 导出和 PDF 创建/预览。
- 文件版本、继续修改、版本切换和比较。
- 任务历史、继续上次、再次使用、失败恢复和部分完成状态。
- 任务记录、文件和记忆影响的独立清理。

### Phase 3：能力扩展

- 运行组件健康检查和真实数据连接。
- 小丑鱼 能力模板、复制和版本升级。
- 基于成功运行的受控能力改进。
- 多角色分工与成本/质量观测。

## 17. 本轮不做

- 不做节点式工作流画布。
- 不做公开能力市场。
- 不暴露能力血缘或原始材料。
- 不把没有实时连接的场景包装为实时可用。
- 不在没有转换器时把草稿伪装成 DOCX/PDF。
- 不通过删除署名规避许可证义务。

## 18. 验收标准

1. 能力中心能脱离聊天独立打开、搜索和运行。
2. 首版启用的能力使用统一的 小丑鱼 名称、ID、契约和状态；数量以真实产品验证为准。
3. UI、API、日志、产物元数据和普通文档不包含原始名称、链接、标识符或提示词。
4. 公开 API 仅返回字段白名单，禁止字段扫描通过。
5. 每项能力都显示输入、输出、运行条件和事实边界。
6. 辅助模式不会显示为实时已确认。
7. 运行刷新后仍可追踪，并产生可打开的文件和审计记录。
8. “继续上次”能恢复目标与材料；“再次使用”会新建任务，不覆盖原记录。
9. 任务历史、文件版本和记忆影响有独立入口与清理边界。
10. 许可证要求与净化策略不存在冲突。

## 19. 待确认问题

“开发者也不能知道”是否包含 Git 提交历史、现有克隆和已经接触过当前代码的成员？

- 如果只要求未来的产品与普通开发仓库不可见：清理工作树、重写定义并增加扫描门禁即可。
- 如果要求拥有完整仓库权限的未来开发者也无法从历史发现：需要新建洁净仓库，或经过授权后重写 Git 历史；仅修改当前文件不够。
