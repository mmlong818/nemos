# 能力中心 × 记忆系统设计补充

状态：Design v0.1
日期：2026-08-04
原则：少而有效，不新建一套偏好系统

## 1. 设计目标

能力中心应当记得用户长期稳定的交付习惯，让同一项能力越用越顺手，但不能让记忆覆盖当前任务、事实准确性或安全规则。

首版只处理 4 类高价值偏好：

1. **工作习惯**：先给结论还是先给过程、默认详略程度。
2. **文笔**：语言、语气、句子长短、是否使用专业术语。
3. **排版**：标题层级、列表或表格偏好、是否使用摘要和目录。
4. **交付格式**：常用 MD、DOCX、PPTX、PDF、HTML 或纯文本。

不在首版记忆颜色、按钮位置、动画、每个能力的几十项参数等低价值细节。

## 2. 复用现有记忆底座

不新增独立“用户偏好数据库”。继续使用 小丑鱼 已有记忆层：

- `personal_semantic`：长期稳定的个人偏好，例如“偏好简洁、正式的中文表达”。
- `procedural`：可复用工作方式，例如“报告先给结论，再给依据和行动项”。
- 反思整合：把多次一致反馈沉淀成稳定习惯。
- 矛盾失效：新偏好确认后让旧偏好失效。
- 领域路由：写作偏好优先影响内容能力，工作流程偏好优先影响对应任务领域。

现有能力运行已经能够召回相关记忆，但仅按任务文本检索不足以稳定命中跨任务表达偏好。因此增加一次小型“交付偏好召回”，不扩大通用记忆上下文。

## 3. 运行时优先级

```text
安全与事实边界
  > 当前任务明确要求
  > 用户本次临时选择
  > 已确认的长期偏好
  > 小丑鱼 默认值
```

示例：

- 记忆里偏好 DOCX，本次明确要求 HTML：输出 HTML。
- 记忆里偏好简短，但任务要求完整合同：保证完整性，不强行缩短。
- 记忆里偏好少表格，但数据比较明显更适合表格：可以使用必要表格，并保持克制。
- 偏好不得改变来源核验、风险提示、审批或敏感数据处理规则。

## 4. 轻量召回策略

一次能力运行执行两类召回：

1. **任务相关记忆**：与任务主题、对象和历史产物相关。
2. **交付偏好记忆**：只查询习惯、文笔、排版和格式。

交付偏好召回规则：

- 只读取 `personal_semantic` 与 `procedural`。
- 每次最多应用 4 项。
- 优先高置信、近期确认、重复出现且仍有效的记忆。
- 临时、冲突、陈旧或低置信偏好不自动应用。
- 不把完整聊天记忆塞入任务 prompt。

建议形成一个短小的运行块：

```text
本次已应用的交付偏好：
- 中文，表达简洁自然
- 先给结论，再给依据
- 三级以内标题，表格只在比较时使用
- 未指定时默认输出可编辑文档

如与当前任务冲突，以当前任务为准。
```

## 5. 记忆写入规则

### 立即记住

只有用户明确表达长期意图时立即沉淀，例如：

- “以后报告都先写结论。”
- “我不喜欢满篇表格。”
- “正式文档默认给我 DOCX，汇报默认给我 PPTX。”
- “写东西不要太营销。”

### 重复后记住

以下内容至少出现 2 次一致纠正后再沉淀：

- 用户连续把长文改短；
- 多次要求删除 emoji；
- 多次把段落改成列表；
- 多次更改同一种默认格式。

### 不进入长期记忆

- “这一次写得活泼一点。”
- 某个客户、项目或文件的特殊格式。
- 模型偶然采用但用户没有确认的风格。
- 系统根据一次点击推测出的偏好。

这类信息只作为本次任务或对应项目的临时约束。

## 6. 用户界面

能力运行面板只增加一个轻量区域：

```text
个性化                           [使用我的习惯 ✓]
已应用 3 项：简洁中文 · 先结论 · 默认可编辑文档   [查看]
```

展开后仅允许：

- 查看本次应用的偏好；
- 单项“本次不用”；
- 跳转到统一记忆管理页修改或删除。

不在能力中心重新提供完整记忆编辑器，也不为每项能力建立复杂偏好表单。

## 7. 运行结果反馈

产物页提供两个低打扰反馈动作：

- `符合我的习惯`
- `调整表达或格式`

第二个动作打开简短修改框。修改要求先用于当前产物；只有用户明确说“以后都这样”，或相同纠正重复出现，才进入长期记忆。

系统不使用笼统点赞自动推断具体偏好，因为无法知道用户满意的是事实、内容还是排版。

## 8. 建议数据契约

能力运行请求增加一个简单开关：

```ts
interface CapabilityRunPersonalization {
  useMemoryPreferences: boolean;
  ignoredPreferenceIds?: string[];
}
```

运行记录只保存本次应用过的记忆 ID 与版本，不复制完整记忆正文：

```ts
interface AppliedPreferenceRef {
  memoryId: string;
  revision: string;
  category: "habit" | "writing" | "layout" | "format";
}
```

这样可以解释“为什么这次这样写”，同时避免在运行日志中扩散用户记忆内容。

## 9. 隐私与隔离

- 只读取当前用户、当前可见范围内的记忆。
- 角色自己的经历和口吻不能被当作用户偏好。
- 文档中第三方作者的“我喜欢”不能写入用户偏好。
- 敏感记忆默认不参与风格个性化。
- 自动任务沿用创建任务时的个性化开关；每次运行重新读取有效偏好。
- 删除或纠正偏好后，后续运行立即停止使用旧版本。

## 10. 首版实施范围

### 必须有

- 4 类偏好召回。
- 每次最多应用 4 项。
- 当前任务覆盖记忆。
- “使用我的习惯”总开关。
- 本次忽略单项偏好。
- 明确表达或重复纠正后才写入长期记忆。
- 运行记录保存偏好引用，不保存偏好全文。

### 暂不做

- 每项能力独立的复杂偏好页面。
- 自动学习几十种视觉和交互细节。
- 根据一次点赞自动推断风格。
- 让记忆影响事实核验、安全边界或权限审批。
- 对用户展示记忆层、向量、置信算法等内部概念。

## 11. 验收标准

1. 未指定格式时，系统能采用用户已确认的默认交付格式，包括文档与演示格式。
2. 当前任务与记忆冲突时，当前任务稳定胜出。
3. 一次运行最多注入 4 项交付偏好。
4. 临时要求不会自动变成长期习惯。
5. 用户能看见本次应用了哪些偏好并选择本次不用。
6. 删除或纠正偏好后，后续任务不再使用旧偏好。
7. 用户偏好不会跨用户、跨不可见会话或混入角色自身记忆。
