# 多任务排队与取消验收

使用 agent-browser 独立 Edge 会话、本地模拟模型和临时数据目录。未使用 8787 用户服务、真实模型或用户资料。合成任务通过真实 HTTP API 创建，浏览器完成查看、取消及刷新后的核对。

## 实际结果

1. 提交 A、B、C，挂起模拟模型响应。页面显示 A 为“模型执行中”，B/C 为“等待处理”。
2. 在页面打开 B，点击“取消本次任务”。列表与详情转为已取消，A/C 不受影响。
3. 放行模拟响应，A/C 均 succeeded、B cancelled。模拟服务只收到两次对应的模型请求，没有 B 的调用。
4. 重新加载任务页，列表保留三项终态；打开 C 显示最终交付和复制/下载入口。
5. 新增自动集成测试重复上述 API 流程，并重启隔离服务，确认状态保持及模型调用次数未增加。

独立浏览器已关闭，隔离服务已停止；测试框架清理其专用临时数据目录，合成任务不保留，截图及测试源码保留。没有删除用户数据。

## 范围与注意事项

当前 JobWorker 串行领取任务，所以这次实际触发的是任务队列等待，而非多个已领取任务争抢同一模型名额。不能把“等待处理”截图称作“等待模型”实机验证。模型资源并发和状态通知另有单元测试，浏览器层跨入口争抢仍待验收。

一次基于完整拼接文本的浏览器 wait 超时；随后服务状态查询确认任务已完成，重新加载后的快照和详情均正确。本轮不据此声称已验证无刷新自动更新的精确时延。
