# 助理对话与后台任务共享模型的隔离验收

通过真实 /api/chat/stream 与 /api/assistant-team HTTP 入口，使用本地模拟模型、全新数据目录，验证跨入口模型竞争；不是直接调用调度器的单元测试。

## 已通过

1. 助理流式回复占用模型名额，保持模拟响应未结束。
2. 后台任务 A 被领取后，列表摘要与详情最新检查点均显示模型 waiting；任务 B 尚未领取，为 queued。
3. 取消 A 后 A 为 cancelled 且摘要清除等待；B 被领取并转为模型 waiting。
4. 放行助理响应，B 获得名额，记录 active，最终交付成功。
5. 模型请求核对：取消的 A 为 0 次，B 为 1 次，助理回复 1 次；正常对话另外触发记忆分析 1 次。记忆分析使用 makeConnectionAgentModel，同样经过资源调度。

第一次测试把助理相关请求总数预期为 1，实际为 2。检查模拟服务的系统提示确认额外请求为记忆分析器，修正验收口径并显式断言，不隐藏辅助调用。ChatBody 的 memoryWriteMode 字段不是该 HTTP 接口控制记忆写入的有效开关，测试已移除该无效参数；本轮没有改变生产记忆策略。

新增 model-cross-entry.test.ts；与任务排队取消集成、调度单元测试合计 9 项通过，类型检查通过。没有真实模型费用，没有修改用户任务或重启 8787。

本轮是服务接口全链路验证，不是浏览器跨入口操作录像。现有任务 JobWorker 仍串行领取，本轮没有提高并发。辅助调用同样必须纳入未来全任务预算；持久等待顺序、429 退避和工具锁仍待实现。
