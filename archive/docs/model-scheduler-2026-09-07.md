# 跨任务模型请求排队：第一阶段

接入位置：llm.ts 的 makeConnectionAgentModel，覆盖经过该统一入口的 OpenAI-compatible、Responses、Anthropic 流式和非流式调用。不是所有外部请求的全局拦截器；独立 embedding、语音、视觉及绕过该入口的调用未纳入。

同一服务 origin + 凭据共享进程内名额，不按模型名或协议拆分。默认容量 1、最多 128 个等待请求；先进先出。不同 origin/凭据独立，但同账号不同 Key 可能仍共享供应商额度，后续需显式账户资源组。资源标识为带进程随机盐的 HMAC，不含原始凭据。

等待取消移除请求，不调用模型；异常时 finally 释放名额。已开始且不响应取消的底层请求仍占用名额，直至请求真正结束，不能因本地取消就放行另一个请求造成超额并发。流式请求持有名额直至响应消费结束。模型回复后释放，不锁住后续工具或人工审批。

验证：39 项相关单元测试通过，类型检查通过。新增 6 项包括两个独立模型适配器实际共享名额、FIFO、独立资源、取消、失败释放、并发/等待上限、凭据标识。网络响应模拟，无真实模型费用。

边界：这是模型请求准入层，不是持久任务调度器。现有任务仍由原队列保存；进程内等待顺序未持久化，重启只依靠原任务恢复机制重新申请名额。当前阶段的超时可能包含排队时间，后续需要分开等待超时和执行超时。未实现页面排队位置、资源优先级、跨进程租约、429 Retry-After 退避、跨 Key 账户额度组、工具互斥和总预算。

本次修改没有重启 8787 服务；新逻辑需要下次启动加载。没有更改用户连接配置或任务数据。
