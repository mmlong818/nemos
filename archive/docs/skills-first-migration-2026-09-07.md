# 小丑鱼：主助理与技能库的第一轮调整

## 已落地

- 保持助理、任务、文件、记忆四个主入口。管理区的“我的 Bot”成为“技能库”；旧 `/bots`、任务深链接、接口与记录 ID 保留。
- 区分“规则模板”和“执行技能”。当前本机显示 10 项文字规则、11 项执行技能；不把一段提示词描述成拥有工具或私人记忆权限的独立智能体。
- 11 项执行技能保留原执行器、材料处理、格式与授权。目录中的通用 Bot 后缀移除；用户保存的名称和规则不改写。
- 技能详情采用统一描述：适用场景、输入、处理方法、交付、权限、限制和核对方式。旧规则缺少结构化信息时明确提示以原文为准，不利用旧模板资料猜测用户修改后的行为。
- 新建规则以五部分定义：适用场景、输入材料、处理步骤、交付要求、边界与缺项；编译成原执行链路实际使用的 instructions，不新增平行存储。缺项、单项超长、总长超过 4000 字及混入其他字段标题均拒绝保存。
- 已有规则仍以完整原文编辑，保留版本冲突检测；从模型结果审阅规则草稿的路径仍保留原文审阅，不强行转成结构化表单。
- 任务中的规则选择为可选；默认自动匹配文字规则，用户也可独立完成或手选。专业执行技能仍从技能库准备，未声明全部自动调度。
- 市场改为“技能市场”，仍明确尚未开放，不上传规则和数据。
- 技能目录减少无效卡片高度、提高摘要字号；沿用现有配色、导航与组件。工具页运行时旧标题修正为“工具与连接”。

## 不变的安全与数据边界

- 未修改真实数据库、已有规则、记忆、模型连接、附件和任务记录。
- 没有重启 8787 服务；本轮静态资源与页面修改在刷新后生效。
- 文字规则仍不具备工具、联网或私人记忆读取权限。文字说明不替代后端权限控制。
- 执行技能仍使用原授权与模型服务，不因打开详情或准备页而执行。
- 这不是标准 SKILL.md 包导入器，也不是已经接通的在线市场或统一技能调度器。

## 验证

- 132 项相关单元与隔离回归测试通过，0 失败；`npm run typecheck` 通过。
- 新增 7 项技能定义测试：规则编译/解析、输入验证、旧规则不变、流程映射、真实内存 SQLite 保存和冻结计划、表单新建与编辑请求、兼容入口。
- 浏览器桌面 1440×1000 与小屏 390×844 检查：技能库、详情、规则编辑、选用规则、原演示准备页、默认任务和未开放市场；无页面脚本错误。
- 浏览器新建与旧规则保存均拦截 `/api/assistant-team/bot`，仅捕获合成/原样请求后返回模拟成功，不写入真实服务。新建规则实际持久化与计划冻结由内存 SQLite 测试覆盖。
- 已确认旧规则 ID、revision、instructions 在编辑请求中保持一致；选用资料整理规则后，任务中的对应选项被选中。
- 未运行付费模型、真实文件生成或外部工具，故不将本轮验证称为完整 AI 能力验收。

## 后续仍需实现

1. 在统一任务入口中规划与调用执行技能，保留确认、权限、模型和交付边界；不要只改预览文案。
2. 统一任务与成果来源，打通已有文件选择、成果找回、继续修改、项目与跟进。
3. 若要兼容外部技能包，独立定义清单、版本、依赖、来源、沙箱与验收协议；不能把任意下载的提示词或脚本直接授予工具权限。
4. 前一轮审查中的草稿跨页恢复、模型选择组件统一等问题仍需专门完成；本轮未把它们标记为已修复。
